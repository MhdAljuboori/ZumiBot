# Message search

**Message search (`core/search/searchIndex.ts`, `shared/src/search.ts`, `components/MessageHits.tsx`, `net/useMessageSearch.ts`, `state/messageSearch.ts`, `searchHighlight.ts`).** The sidebar's search box (Agents mode, its search button) still filters agents and chats by name, and under them lists **Messages** (the Ctrl+K palette lists the first few too, see [Command palette](ui.md)): `chats:search {query, offset}` hits from a full-text index over every chat's visible messages, archived and A→B chats included. **Index.** `SearchIndex` lives in memory only (nothing on disk, never synced, never logged): `start()` builds it after the server listens, reading every chat through `ChatStore.loadItems` one chat at a time with a `setImmediate` between them (searches meanwhile carry `indexing: true` and the client asks again every 1.5 s), and `stop()` ends it before the lock is released. The store's items listener hands every save to `note`, which indexes a chat 2 s after its first unindexed save (a running turn saves about once a second), with the newest items; the new removal listener (`ChatStore.setRemovedListener`, every `remove` path, a failed fork or clone included) drops a chat at once. A chat saved or removed while the build reads it keeps what the listener saw. Only `user` and `assistant` items with text are indexed (never tools, results, approvals, notices, the hidden result of a Run button (`run` on a user item, see [Run button](run-blocks.md)), side questions, dispatch entries or hidden versions), their first `SEARCH_TEXT_MAX` (100 000) characters. Words map to message numbers; a changed message gets a new number and the old one is dropped lazily (a rename or restamp updates the entry in place), and the lists are rebuilt once dead entries outweigh live ones (and are at least 5 000). The handler passes only listed chats. **Matching** (pure, shared, so the server's marks and the client's highlight agree): text is folded (NFKD, marks dropped, lowercased, Arabic tatweel, alef wasla, alef maqsura, ta marbuta and Greek final sigma normalised) and split into letter-and-digit tokens cut at 40 characters, each Han, Hiragana or Katakana character a token of its own; an Arabic token is also indexed without a leading article or particle (`ال`, `وال`, `ولل`, `بال`, `كال`, `فال`, `لل`, `و`). Every word must match (AND, at most 8); a word of 2+ characters matches word starts, a shorter or quoted one whole words; a chunk joined by punctuation (`v8.6.5`, `foo.bar`, a CJK run) and a quoted phrase must also stand as typed from a word's start (a closed quote also ends at a word's end), checked on the plain text against the newest 2 000 candidates (`capped` past that). Hits are newest first, 30 a page (`SEARCH_PAGE`, offset at most 990), each with a snippet of about 180 characters around the first match, Markdown marks dropped (`plainText`), and its `marks`. **UI.** Each hit shows its chat's title, an Archived tag, when, who wrote it and the snippet with its marks; **Show more** adds the next page. A click opens the chat (`openMessage` in `App.tsx`: through the unsaved-changes guard, from any mode, closing the drawer on a phone) and, once its view has mounted (a request present at mount reads as already handled), sends `showRequest` with the query: `MessageList` waits for the first page, loads older pages with `until` (`chats:items`' optional item id: the page reaches back to that item and `JUMP_LEAD` (10) items above it, at most `ITEMS_JUMP_MAX` (600) items, so a jump to an old message, a search hit or Show in chat, loads in one request instead of a page at a time; an id not in the list is ignored), scrolls instantly (a smooth scroll to the top of the loaded items would load the next page under it), flashes the bubble, and lights the query's words in it with the CSS Custom Highlight API (`::highlight(search-hit)`, `--search-hit`; no DOM change, nothing where the API is missing), cleared on the next jump or when the list unmounts. A search jump opens no tool runs. Sizes: a synthetic 50 000 messages (about 40 MB of text) built in 3.4 s and took about 106 MB of heap, text included; word queries answered in 1-25 ms.

The tray keeps ZumiBot running when no window is open. The island is a thin strip of agent icons on the right edge of your screen. One click on an icon opens a small chat with that agent, over whatever you are doing.

This page describes Linux, the system the desktop app has been built and tried on most. On a Mac the same parts are there, with the differences listed under [On a Mac](#on-a-mac). The island and the tray are part of the desktop app only. They are not in a browser.

## The tray

ZumiBot puts an icon in the system tray. Hover over it and it reads "ZumiBot". Open its menu for three items:

- **Open** shows the ZumiBot window.
- **Sponsor ZumiBot** opens the sponsor page in your web browser.
- **Quit** closes ZumiBot completely.

Closing the window does not quit ZumiBot. It only hides the window, and everything keeps running: a Local server, your agents' replies, [routines and workflows](/automation/routines/), and the island. Open the window again from the tray, or start ZumiBot again from your applications menu. The second start does not run a second copy. It shows the window that is already there.

Quitting asks first when something would be lost:

- Unsaved edits to an agent: "You have unsaved changes to this agent." Choose **Save**, **Discard** or **Cancel**.
- Replies in progress: for example "2 replies still running. Stop them and quit?" Choose **Stop & Quit**, or **Cancel** to stay. If background processes would stop too, the message says so.

## Put agents on the island

By default nothing is on the island. With no agent picked, there is no strip at all.

1. Open **Settings**, then **Island & startup**. This section appears only in the desktop app.
2. Under **Agents on the island**, tick the agents you want. You can pick up to 10. An agent whose file has a problem shows "Can't be added: its file has a problem."
3. Order them with **Move up** and **Move down**. The strip lists them in this order, from the top. The line under the list says so: "Up to 10 agents, in this order from the top."

The strip appears on the right edge of your screen, on every workspace, and stays on top of other windows. It does not take the keyboard focus until you click an icon, and it does not show in the taskbar or in Alt+Tab.

Each server has its own list, because agents differ from server to server. The island shows only while the app is connected to a server.

## Chat from the island

Each icon is an agent. Marks on an icon tell you what is going on:

- A spinning ring: a chat with that agent is working.
- An amber number: that many things wait for you, such as an approval card or a question.
- A blue dot: a reply you have not read yet.

1. **Click an icon.** A chat opens beside the strip. It picks the chat for you: the one that has waited longest for an answer, else the chat you last had open here, else the newest one with an unread reply, else the newest chat. An agent with no chats yet shows its introduction and a message box. A line under the box reads "Runs in" and the name of the folder where the chat starts.
2. **Type a message and send it.** It is an ordinary chat. Approval cards, questions and plans are answered in the popup itself.
3. **Use the ⋯ button for more.** Its menu has **New chat**, the agent's **Recent chats** (the newest 8, with the same marks), and **Open in ZumiBot**, which opens this chat in the main window.
4. **Close it.** Choose **✕**, press Esc, or click the icon again. Esc first closes an open menu.

The island lists only an agent's own single chats. Group rooms, archived chats and chats made by a workflow are not on it.

To move the strip up or down, drag its background. ZumiBot remembers where you left it.

## Talk to an agent with the shortcut

A keyboard shortcut starts a [voice request](/voice/voice-requests/) from anywhere, even with no agent on the island. The default is Ctrl+Alt+Space. Press it to start listening and press it again to stop. When the request is sent, the popup shows the new chat, and the agent's reply appears there. You can change or turn off the shortcut under **Settings**, **Island & startup**, in the **Voice shortcut** row. If another app already uses the keys, Settings says "That shortcut is taken by another app."

## Start at login

The **Start at login** switch is in **Settings**, **Island & startup**. It is on by default. Its hint reads "ZumiBot opens in the tray when you sign in, without a window." Turn it off to stop that.

When ZumiBot starts this way, it connects quietly. If the server is not ready yet, it tries again every 10 seconds for about two minutes. After that it shows the window with the error. If your server needs a sign-in, the window opens at once, because only you can sign in.

## On a Mac

- **The menu bar instead of a tray.** ZumiBot's icon sits in the menu bar at the top right, with the same menu: **Open**, **Sponsor ZumiBot** and **Quit**. ZumiBot also stays in the Dock while it runs. Click the Dock icon to show a closed window again.
- **Quitting.** Cmd+Q and the Dock's **Quit** ask the same questions as **Quit** in the menu.
- **The island** is on the right edge of the screen, above other windows and on every desktop. Clicks beside the strip reach the window under it.
- **The voice shortcut** is Ctrl+Alt+Space, as on Linux. The first voice request asks for the microphone; choose **Allow**.

## Tips and limits

- **The popup is small on purpose.** It has no side panel, no context meter, no cost chip and no model or effort pickers, and it has no Export. Type `/btw` there and it says "Side questions open in ZumiBot" and sends nothing. A typed `/run-workflow` says "Workflows start in ZumiBot". Use **Open in ZumiBot** for those.
- **Drafts stay in the island.** A message you have not sent is not shared with the main window, and it is gone when you restart ZumiBot.
- **Notifications are unchanged.** They still come from the app as before.
- **Linux desktops.** The island has been built and tried on Ubuntu with GNOME on X11. On a Wayland session your desktop decides whether the strip can stay on top or on every workspace, so it may not behave this way.
- **The tray icon needs a tray.** Ubuntu shows it through its AppIndicator extension. If your desktop shows no tray icons, you will not see the menu, so use your applications menu to bring the window back.
- **If you move the AppImage file,** start it once from its new place so the login entry follows it.

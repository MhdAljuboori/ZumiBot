# Voice input

**Voice input (`core/voice/`).** A mic button in the composer and the message edit box dictates text at the caret. Tap to start, tap to stop. `useDictation.ts` records with `MediaRecorder` (Opus/webm, else ogg or mp4; `getUserMedia({audio: true})`, never video) and POSTs the clip raw to `/api/voice/transcribe` (`http/voice.ts`, behind the gate like every route; 8 MB, 2 at once, 30 a minute, held in memory only, never written to disk). `transcriber.ts` sends it to OpenRouter as `elevenlabs/scribe-v2` with `provider: {zdr: true}` (zero data retention); an upstream answer that is not the expected JSON is a plain 502 `upstream`, never passed through. **Cleaning** (both off by default, `clean` in `voice.json`): after Scribe answers, `handleTranscribe` runs `cleanTranscript` (`core/voice/cleaner.ts`). "Remove filler words" cuts standalone hums with `stripFillers` (`shared/src/voiceWords.ts`): English from the `FILLER_WORDS` table (uh, um, er, ah, hmm, mm, ...; letter runs of three or more fold to two first, so "ummm" matches), Arabic only with three or more م or alefs (ممم, اممم, ااا), since "مم" (مِمَّ) and "امم" (أمم) are words. It never cuts `اه`/`آه`, "mhm", "mm-hmm" or "uh-huh" (they mean yes), an all-caps abbreviation (ER, UM, HM), "mm" after a number, or a bare "Um"/"Umm" before a capitalised name ("Umm Ahmad"; before "I" it is still a hum). It tidies what it leaves: a dropped sentence end moves onto the word before, a dropped mid-sentence comma takes the comma before it ("to, uh, go" is "to go"), a capitalised hum at a sentence start passes its capital to an all-lowercase next word, and line breaks stay; text with no hum comes back unchanged. "Fix mistakes with AI" also runs that filter, then sends the text to OpenRouter's chat completions as `anthropic/claude-haiku-5.5` (`CLEAN_MODEL`, `reasoning: {effort: 'none'}` because it thinks by default and thinking shares `max_tokens`, `provider: {zdr: true}`; it takes no `temperature`), with one fixed system prompt (`CLEAN_SYSTEM`: the text is something said, never a message to answer; drop fillers, stutters and false starts, keep only a self-correction, keep the language and dialect, names, numbers, @mentions and /commands, add nothing) and the transcript inside `<transcript>` tags. Scribe's own no-verbatim mode was tried and not used: it keeps self-corrections and turned Levantine Arabic into formal Arabic, which would also break the Arabic routing phrases and aliases. The rewrite never fails a transcription: no key, an HTTP error, a non-JSON answer, a 20 s timeout (`CLEAN_TIMEOUT_MS`, for a five-minute dictation) an answer that did not finish with `finish_reason: stop` (cut at `max_tokens` or filtered, which would silently drop the end of a dictation), or an answer that looks like a reply instead of a cleanup (empty, longer than 1.5 times the input plus 40 characters, echoing the tag, or with fewer than half of its words, after `normalizeUtterance`, among the words said, as a refusal or an answer to a dictated question would be) falls back to the filtered text; logs carry the status and the character count only. It is skipped for 3 words or fewer, and when the request's `X-ZumiBot-Voice-Clean` header (`VOICE_CLEAN_HEADER`) is `light`; the header is `full` or `light`, absent is `full` (a page loaded before it existed), anything else is 400 `bad-request`. Dictation and a voice request both send `full`; `light` stays for a caller that must not be rewritten. The switches are read per clip (`VoiceStore.clean()`), so a flip applies to the next one. The state machine is pure, in `frontend/src/state/dictation.ts` (events carry a `run`, so a late permission or transcript after a drop is ignored and the mic released); the hook only does the I/O. Recording stops on a tap, at the 5-minute cap, or when the page is hidden (all three are transcribed) and is dropped on unmount (chat switch, leaving the new-chat screen, closing the edit box): nothing inserted, nothing sent. The mic is released at every stop, and clips under 0.6 s are never uploaded. Send while dictating holds the send until the transcript is inserted, then sends once through the normal submit; Composer clears itself after such a hand-off through its `sends` counter, because React batches the insert's draft update with the send's clear. Inserted text always ends in a space, so a transcript ending in `@` or starting with `/` opens no menu. Dictation dispatches `zumibot:input` (`DICTATION_INPUT_EVENT`, listened to in `useNotifications.ts`), so presence counts it as input. The key, the audio and the transcript never reach logs, URLs, errors or the UI (a failure log has the HTTP status and the clip size). `voice.json` (`voiceStore.ts`) holds `{enabled, key, talk, clean}`, set from **Settings › Voice input** (`VoiceSettings.tsx`); voice is on only when enabled and a key is saved, and `voice:changed` is broadcast. `talk` (`VoiceTalk`, `DEFAULT_TALK`) is the voice requests' settings: `enabled`, `defaultAgent` (null = ask which) and `aliases` (spoken names per agent file name, since Arabic speech may spell an English agent name in Arabic script). The file read takes it field by field, so an old `{enabled, key}` file or one wrong value reads as the default for just that field; `set` merges a talk patch over the saved one. `clean` (`VoiceClean`, `DEFAULT_CLEAN`) is `{fillers, rewrite}`, both `false` by default, read field by field the same way; `voice:set` takes a `clean` patch of those two booleans (`parseCleanPatch`) and answers `bad clean settings` otherwise. `VoiceStatus` carries `talk`, `talkOn` (voice on and `talk.enabled`) and `clean`, never the key. `parseTalkPatch` (`shared/src/voice.ts`) checks a patch (names at most 100 characters, 50 agents, 10 phrases each, a phrase 1-60 characters after trim, no control characters) and `voice:set` answers `bad talk settings` otherwise. The settings page shows a **Clean up speech** group while voice is on, with the two switches ("Remove filler words", "Fix mistakes with AI"), saved at once. It shows the talk part only while voice is on too: a switch, a default-agent select (loadable Claude agents, never Zumi Bot or Codex) and an alias list per agent (`state/talkSettings.ts`), saved when an input loses focus or a phrase is removed. The mic is hidden, not dead, where it cannot work: voice off, no recorder support, or an older shell that denies the mic. The shell's `isPermissionAllowed` (`navigation.ts`) allows `media` for the connected server's origin only when every requested type is audio; video, other origins and `file:` are refused. `SECURITY_HEADERS` (`http/headers.ts`) sends `Permissions-Policy: camera=(), microphone=(self), geolocation=()`. `styles.css` gives each block and the edit box `unicode-bidi: plaintext`, so Arabic dictation reads right to left. Design: `docs/superpowers/specs/2026-11-02-voice-input-design.md`.

**Voice chats (server).** The request loop, routing and the phone and desk surfaces are in [Voice conversations](voice-conversations.md); this part is the chat's side of it. `chats:createVoice(agentName)` (`rpc/handlers.ts`) makes a single chat with `voice: true` and the title `Voice · <Mon D>` (`voiceChatTitle`, `core/voice/voiceTitle.ts`, in the page's time zone). It refuses an unknown or broken agent and Zumi Bot (`matchAgent`); a Codex agent is fine. The folder is the new-chat screen's: the built-in one, else the agent's last, else home. Apart from the sidebar's mic mark (`ChatMeta.voice`) the chat is an ordinary one: its turns, approval cards, remembered approvals and side runs are the same as in any chat. Voice no longer speaks: there is no speech route and no spoken reply.

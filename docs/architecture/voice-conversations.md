# Voice conversations

**Voice requests.** Speak a request to an agent, in English or Arabic, and it is transcribed and sent to a new chat, which then opens on screen: "Ask Work Assistant to set a meeting with Obada tomorrow after 3pm". Nothing is read back and no card is asked by voice; the follow-ups happen in the chat (the composer's mic, [Voice input](voice-input.md), or another press of the shortcut for a new request). It runs in the browser on two surfaces, the installed phone page (`/voice`, screen on) and the desk island (a global shortcut in the desktop shell), and builds on voice input (same key, same gate, same privacy rules). The spoken version (replies and cards read aloud, forced approval cards) is kept on the git branch `voice-spoken-replies`. Not built: a locked screen, a wake word, group rooms, switching agents mid-talk, other callers (Alexa and the like).

**The flow and the pure modules.** `useVoiceTalk.ts` is the only place that does I/O (`getUserMedia`, `MediaRecorder`, an `AnalyserNode`, the wake lock, `api.chats`); every decision is in pure modules under `frontend/src/state/`, so they are unit-tested (there are no DOM tests). `voiceTalk.ts` is the machine, `step(state, event) -> {state, effects}`: `idle -> listening -> transcribing -> sending -> ended`. Events: `start`, `stop`, `clipDone`, `heard`, `noSpeech`, `transcribeFailed`, `routed`, `chatReady`, `sent`, `sendFailed`. Effects: `acquire` (wake lock and mic), `listen` (one clip), `transcribe`, `route`, `createChat`, `send`, `release`, `open{chatId}`. The page listens once; the clip is transcribed (`/api/voice/transcribe`, lang `auto`, full cleaning like dictation, see Cleaning in [Voice input](voice-input.md)); the text is routed; `chats:createVoice` makes the chat and `chats:send` sends the request under a client message id. The message counts as sent the moment the chat's items push carries it (`messageInPush`), not when the turn ends, since `chats:send` settles only then; a rejected send is decided by `sendOutcome`: a dropped connection (`NOT_CONNECTED`) is unknown, not failed, so the chat is opened anyway and resyncs after the reconnect; any other rejection is a failure unless the chat already holds the message (one `chats:items` read). On `sent` the machine emits `release` and `open{chatId}`: the mic and the wake lock go, and the host shows the chat (the page navigates to `/chat/<id>`, the island's popup switches to that chat, the agent's ordinary chat popup, picked or not, and the window stays while it is shown; see Voice shortcut in [Desktop shell](desktop-shell.md)). Nothing listens again afterwards. It is modelled on `dictation.ts`: `run` counts talks and every late event carries its run, so one from a stopped talk is ignored; `talkOps.ts` adds a token per async kind (listen, transcribe), `sendId`, `sendRejection` and `messageInPush`. `endpointer.ts` cuts a clip from mic levels: at least 300 ms of speech in all (`MIN_SPEECH_MS`) and then 1 s of quiet (`QUIET_AFTER_SPEECH_MS`) is `clip-done`; 8 s with no speech at all ends the talk (`NO_SPEECH_MS`); a clip that never goes quiet is cut at 60 s (`MAX_CLIP_MS`); `SPEECH_LEVEL` 0.02 RMS is the threshold. A shorter burst (a cough, a door) followed by the same 1 s of quiet is forgotten: the recorder keeps running and nothing is uploaded. The mic asks for echo cancellation, noise suppression and auto gain. The screen wake lock is held from start to end and asked for again when a hidden page returns; the audio context is made inside the starting tap, because a phone only lets a page listen after one. Two transcription failures in a row, a failed send or a failed chat creation end the talk with a notice; a `visibilitychange` to hidden on a page that is not the island, a dropped socket, or talk switched off while it runs (`shouldStopTalk`) end it too, so nothing holds the mic.

**Notices.** The machine carries `notice` (English, like the rest of the UI), shown under the status line: "Didn't hear anything." (no speech, or an empty transcript, ended), "Couldn't understand that." (two failed transcriptions), "Couldn't send that: “<the request>”" (cut at 200 characters, so the spoken words are not lost; followed by the server's own error text when there is one), "I don't know an agent called X." (or "I don't know that agent." with no name heard), and "Who should I ask? Say: ask, then an agent's name." (no usable default agent). Each of those ends the talk (`ended`, mic released) so a tap or the shortcut starts again; the hook adds its own for what the machine cannot know (the mic refused, the connection lost, the server's own error), shown after the machine's. On the desk island the popup closes at once only when a chat was opened or nothing was heard (`talkEndAction`); any other ending keeps the popup up with the notice (and Open chat when a chat exists) until the user closes it (close button, Esc), presses the hotkey again, or `ISLAND_NOTICE_MS` (8 s) passes.

**Routing and aliases.** Only the one utterance is routed (`routeUtterance` in `voiceRoute.ts`). A leading "ask / tell / اسأل / قل ل / قول ل / خلي" plus a name, or a known name followed by a comma ("Work Assistant, what is ..."), names the agent. The name is matched on whole words, longest first, against each agent's file name, its display name and its **spoken aliases** from Settings (`talk.aliases`, for Scribe writing an English agent name in Arabic script); everything after the name (past "to" / "ان") is the request, cut from the original text. After a leading phrase only, a name with no exact match may be **misheard**: Scribe spells an unusual name its own way ("Workiom Master" heard as "workium master"), so `nearestAt` compares each phrase with the next words (as many, one fewer or one more, since a name may be split or joined) by edit distance (Damerau, per code point), allowing none under 5 letters, one from 5 and two from 10 (`slack`); it routes only when every phrase that close belongs to one agent, and the request starts after the words actually said. A pronoun object ("tell them") is checked first, and a vocative stays exact, since any sentence opening with a word and a comma would risk a match. No leading phrase sends it to `talk.defaultAgent` (default `work-assistant`); no usable default is `no-agent`. A name that is asked for but not found (exactly or nearly) is `unknown` and never falls back to the default, since that would be a guess; the same phrase on two agents is `unknown` too. "Tell me ..." / "قل لي ..." is a plain request, not an address. A Codex agent is routed like any other. A remote (AG-UI) agent is never routed to: `routeUtterance` drops it before matching, so naming one is `unknown` and a remote default is `no-agent` (`talkAgents` leaves it out of Settings too). A named agent with no request ("Ask Work Assistant") shows "What should I ask Work Assistant?" and listens once more: that next utterance is the request (it keeps the agent, so it is not routed again; silence then ends the talk). `matchAgent` (`shared/src/agentMatch.ts`, also used by the backend's `agentResolver`) is the one place that refuses broken agents and Zumi Bot and treats several hits as unknown. `chats:createVoice` (see [Voice input](voice-input.md)) makes a chat with `voice: true`, title `Voice · <Mon D>` and the folder the new-chat screen would use; the chat shows a mic mark in the sidebar and is an ordinary chat in every other way (approval cards on screen, remembered approvals, ask bridge, side runs). Renaming an agent moves the default agent and the alias key in `voice.json` too (`VoiceStore.renameAgent`, in the `agents:save` order after settings and the sidebar, before routines; a failure is logged and never fails the rename). Words live in `shared/src/voiceWords.ts` (`normalizeUtterance`, `ASK_PREFIXES`, and the filler table the transcript cleanup uses).

**The phone page and the desk shortcut.** `/voice` (`VOICE`, `voiceFromPath` in `shared/src/appPaths.ts`) is a full-screen `VoiceTalkView` over the app, which stays mounted under it so an open editor keeps its edits; Back only shows or hides it. The agent's avatar (the agent the talk went to, else the default agent; a blue dot while it listens; tapping it starts a talk), a dotted waveform under it (`VoiceWave`, redrawn every animation frame from the hook's `level()` without re-rendering React; `state/voiceWave.ts#waveDots` follows the voice while listening, flat in silence, and pulses while it transcribes or sends; still under reduced motion), one status line (`talkStatus`: Tap to talk, Speak now, Thinking…, Tap to talk again), a small Stop, and Open chat when a chat was made but the request did not go. The phone top bar's mic button (`MobileBar`, `talk-button`) opens it and starts listening; `manifest.webmanifest` has a `shortcuts` entry "Talk" pointing at `/voice?start=1`, so a long press on the app icon starts at once. A start with no user activation on the page shows **Tap to start** (Chrome blocks the mic until a tap), and the mic is not asked for before it. The mic mark is shown only where it can work: voice on, `talk.enabled`, a recorder and an allowed mic (`useTalkShown`). When the request is sent the page closes the voice view and opens the chat (`openChatFromNotification`, through the unsaved-changes guard like any move). On the desk the shell's global shortcut (`Ctrl+Alt+Space` by default, set in Settings › Island; see the Voice shortcut in [Desktop shell](desktop-shell.md)) sends `island:voice` and the island page (`IslandView`'s `voice` slot) mounts the same `VoiceTalkView` compact in its popup with `autoStart` and `noTap` (a global shortcut is no click on the page); when the request is sent the popup closes (`voiceEnded`) and the main window opens at the chat (a talk that ends with a notice keeps the popup up, see Notices); the island still never takes focus. **Settings › Voice input** (`VoiceSettings.tsx`, `state/talkSettings.ts`) holds the switch, the default agent (Codex agents included, Zumi Bot never) and the alias lists (see [Voice input](voice-input.md)), beside the transcript cleanup switches; the shortcut is in Settings › Island (`IslandSettings.tsx`), and one a different app already holds is refused with "That shortcut is taken by another app."

**Where it ends.** Zumi Bot, broken agents and group rooms never get a voice chat. Audio and transcripts never reach logs, URLs, errors or disk. The only settings are `talk` in `voice.json` (see [Data folder](data.md); an old file's `ttsVoice` is ignored) and `voiceHotkey` in the shell's `island.json`; the only chat field is `ChatMeta.voice`. The `e2e:voice` suite (fake claude, a fake OpenRouter that answers transcriptions only, Chrome's fake mic) is the check beyond the unit tests ([E2E](e2e.md)). OpenRouter transcription spend is not in the Usage page.

# Workflow canvas, notes and groups

**Workflow canvas controls, sticky notes and canvas groups (`state/workflowKeys.ts`, `workflowHistory.ts`, `workflowClipboard.ts`, `workflowMenu.ts`, `workflowNav.ts`, `workflowNotes.ts`, `workflowGroupEdit.ts`, `workflowGroupView.ts`, `shared/src/workflowGroups.ts`, `components/WorkflowNotes.tsx`, `WorkflowGroups.tsx`, `WorkflowMenu.tsx`, `WorkflowNodeParts.tsx`).** The editor canvas follows n8n's mouse and keys, in `WorkflowCanvas.tsx` through React Flow props: `selectionOnDrag` (a plain left drag boxes, with `panOnDrag` the middle button only), `panOnDrag` true and no box while Pan mode (the hand, `H`), a touch device (`(pointer: coarse)`) or the read-only run view holds the left button, `panActivationKeyCode` Space/Ctrl/Cmd (React Flow turns `panOnDrag` on while one is held and its box off, which is why Ctrl+drag pans while Ctrl-click, which a node's own drag handler takes before the pane sees it, still toggles a pick through `multiSelectionKeyCode`), `panOnScroll` with `zoomOnScroll` off and `zoomActivationKeyCode` Ctrl/Cmd (a trackpad pinch arrives as Ctrl+wheel), zoom 0.1 to 4 (`ZOOM`), `snapToGrid` on a 20 px `GRID` (a drop or a move snaps, saved positions are never changed on load), `zoomOnDoubleClick` off (a double-click opens the step or edits the note), `elevateNodesOnSelect` off (a picked note stays under steps) and `disableKeyboardA11y` (its own arrow-key moves of a focused node would swallow the arrow navigation). `canvasKey` (`state/workflowKeys.ts`, pure) maps a key to an action: zoom `+ - 0 1`, Shift+S note, N the Add step menu, Ctrl+D, Ctrl+Z and Ctrl+Shift+Z or Ctrl+Y, Ctrl+G, Ctrl+Shift+G, Alt+G and Shift+Alt+G (matched by `code`, since Alt+G types a character on a Mac), arrows (`workflowNav.ts`: along edges, siblings by y, Shift adds every step downstream or upstream, a step hidden in a collapsed group selects the group), F2, Enter, H and Ctrl+Enter; none of it fires while the user types (`isTypingTarget`), except Ctrl+S, and a held N, H, Shift+S or group key does nothing on repeat. A floating bottom toolbar (Select, Pan, Sticky note, Add step, which keeps `wf-add`) and React Flow's zoom buttons with a reset-to-100% one sit on the editable canvas; a run's view keeps only the zoom buttons and pans with the left drag. The Add step menu grows up from the toolbar's button; opened anywhere else (a port's +, an edge's +, a dropped connection, the right-click menu's Add step) it is measured after it renders and fitted into the canvas (`placeMenu` in `state/workflowMenu.ts`), and either way a canvas shorter than its rows caps its height and it scrolls, so the last kinds stay in reach. The right-click menu (`menuItems` in `state/workflowMenu.ts`, drawn by `CanvasContextMenu`, shortcuts named, ⌘ on a Mac) depends on the target (step, note, group header or collapsed group, selection, empty canvas, an edge with its one row Remove connection; a right-click on an unselected item first picks it alone, an expanded group's header opens its menu without changing the selection) and disables, with the reason as a tooltip, what cannot run (the trigger alone cannot be copied, cut, duplicated or deleted; Group names the first rule broken); its Paste pastes `lastClip()`, the last copy made in this tab, while Ctrl+V reads the system clipboard through the document's `paste` event, so no permission prompt shows. Undo and redo (`state/workflowHistory.ts`, pure) keep up to 100 drafts (`HISTORY_MAX`) of the workflow's `Undoable` fields (steps, edges, notes, groups, trigger, name, time zone; never `enabled`, which a switch applies, never the id, never collapse state), and edits that name the same field key (`step:field`, `note:<id>:text`, `group:<id>:name`) within 1 s are one entry, so typing is one undo step; a note editing session passes `fresh` so it never joins an earlier edit, an undo ends coalescing, and a burst ending where it began (the text field's own undo) leaves no entry; Discard changes and a save that ungroups reset it, other saves keep it; Ctrl+Z in a field stays the field's own. The clipboard (`state/workflowClipboard.ts`) is JSON text `{zumibot: 'workflow-clip', v: 1, steps, edges, notes, groups}` written through the `copy` and `cut` events (the trigger never copied, only the edges between copied steps, a group only when all its members are copied, a collapsed group standing for its members) and parsed by `parseClip` with the shared `parseStep`, `parseNote`, `parseGroup` and `parseEdges` (`shared/src/workflowInput.ts`, which `backend/src/core/workflows/workflowInput.ts` now re-exports), so text that is not a valid clip is ignored without a notice; a paste gives every item a new id and every step a unique handle, and rewrites `{{steps.<old>.output}}` only for an old handle that is unique among the pasted steps and names another pasted step (a swap works, a duplicated old handle is left as written); positions keep the layout with the top-left at the pointer (else +40/+40), past `NOTES_MAX` or `GROUPS_MAX` it adds nothing and says so, and the whole paste is one undo step; it works between workflows and tabs. **Sticky notes** (`notes` on the workflow and in the run's `snapshot`, with `groups`; `Note` `{id, x, y, width, height, color, text}`, `NoteColor` 1 to 7 or a lower-case `#rrggbb`; `notesOf`/`groupsOf` read an older workflow as none; at most `NOTES_MAX` 100, text 10 000 characters, size clamped to `NOTE_MIN` 150x80 up to 5 000, `parseNote` rebuilds each key by key and one id space spans steps, notes and groups) are layout only: the engine, `problemsOf`, templates, Inbox and notifications never read them, `WorkflowRunner.start` copies them into the snapshot inside its `structuredClone`, and Duplicate carries them. They are drawn under every step and edge, also while picked, smaller note on top (`toFlow` z-index `-1000` plus an area rank), render their text through `Markdown images={false}` (an image shows its alt text and makes no request, so the CSP stays), scroll when the text is longer than the box, resize through `NodeResizer` while picked (snapped, clamped), and a drag that starts on one moves only the note. Shift+S, the toolbar or the menu adds one centred on the pointer (the click point for the menu, the view's centre for the toolbar), picked and not opened; a double-click, F2, Enter or the hover bar edits its Markdown in a textarea (Esc or a click away lands it, Ctrl+S lands it first, one session is one undo step, no canvas key fires inside it; text typed there or in a group's header field counts as unsaved before it lands, `onTyping`, and every save lands it first, `flushEdits`). Colours are `--note-1` to `--note-7` and `--note-N-border` tokens in `styles.css` (light and dark); a custom colour fills as picked in both themes, its border is the colour mixed toward black or white, and the ink is dark or light by contrast (`noteInk`); the hover bar's popover offers the seven presets, **Custom…** (a colour input and a hex field, `hexInput`) and the last 8 customs, kept per device in `localStorage` `cb.wf.noteColors` (try/catch, works empty). **Canvas groups** (`CanvasGroup` `{id, name, description?, steps, notes}`, at most `GROUPS_MAX` 50, name 1 to 100 characters after trimming, description at most 145 and a blank one absent, no member in two groups, no trigger) wrap a chain of steps and notes in a named box, as n8n's do, and are layout only: a collapsed group still runs every step in it. `groupRuleBreak` (`shared/src/workflowGroups.ts`, pure) refuses a group of fewer than two members or none a step, one holding the trigger, one with a member already grouped, steps that are not one connected chain (edges taken either way), and steps with more than one entry (a member with edges from outside) or more than one exit (edges to outside); `parseWorkflowInput` refuses only malformed groups, and `workflows:save` drops one that breaks a rule (`dropBrokenGroups`) rather than refuse the save, while the editor drops it first on Save and says "Ungrouped <name>: <reason>." (`ungroupNotice`), until then marking the box (or the collapsed node, with a tooltip) red with "Will be ungrouped on save". The box is derived from the members' bounds (`groupBox` in `workflowGroupView.ts`, 24 px padding and a 36 px header), never stored; Ctrl+G, the menu or the inspector makes one (next free "Group N", its name field opens), Ctrl+Shift+G ungroups, Delete removes a collapsed group with its members, a deleted member leaves its group and a group under two members or with no step goes, a step inserted into an edge between two members joins it, and a step dropped on a box does not. Collapse is a view preference, kept per device in `localStorage` `cb.wf.collapsed.<workflow id>` (try/catch, in memory for a workflow not yet saved), never an edit and never in the history; a collapsed group is one `groupCollapsed` node (name, info icon with the description, "N steps", one input when a step has edges from outside and the exit's ports that leave, with `data-state` in a run) whose edges are re-routed through `collapsedView` (inner edges hidden) and whose handles are re-measured with React Flow's `useUpdateNodeInternals` when its handle set changes, since React Flow keeps a removed handle's old bounds; a connection to or from it maps to the real member (`realConnection`), and a drag of it moves every member (`moveGroup`). Expanding is one edit that pushes what its box would overlap to the right, onto the grid and 40 px clear (`expandPush`, cascading, never left, a push never swaps two items' order), except a loose note that fully holds the collapsed node's footprint, which is a backdrop and stays. React Flow node types are `groupBox` (never `group`, which carries React Flow's own CSS) and `groupCollapsed`; z-order is loose notes `-1000` plus rank, then group boxes `-500` (pointer-events off, only the header takes clicks), member notes `-400`, steps `0`, so a box never hides a step or the note inside it. The run view's canvas draws the snapshot's notes and groups (groups expanded) read-only (the collapse state starts empty and is never stored, a header or a collapsed node's click toggles, and a collapsed group shows one state mark from `groupRunState`: failed, then waiting or paused, then running, then done). A client older than this one saves without `notes`/`groups`, which clears them (accepted), and `workflow-runs.json` snapshots of runs made before have none.

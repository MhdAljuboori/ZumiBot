# Side Ask Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Agent A can put a side question (`/btw`-style: no tools, a fork at B's clean point) on the A→B conversation it opened with `ask`, from its main run and from its own `/btw` side answer, and gets B's answer back.

**Architecture:** A second tool, `side_question`, on the existing `zumibot_agents` bridge. `AgentAsks.sideAsk` finds the existing A→B chat and runs `SideQuestions.askFrom` there, which is a plain side question marked `from: A`. A's side run gets one exception in its tool guard (only that tool) and allows only that permission request; B's side runs keep today's guard byte for byte. The UI adds a side-ask card in A's chat, a link chip on A's side entry and a "from @A" line on B's entry.

**Tech Stack:** TypeScript, Node 22, React 19, vitest, MCP SDK stdio bridge, claude CLI stream-json, playwright-core e2e with the fake claude.

**Spec:** `docs/superpowers/specs/2026-11-05-side-ask-design.md`

## Global Constraints

- Tool name `side_question`, full name `mcp__zumibot_agents__side_question`. Input exact keys `agent`, `question`; question 1 to 4 000 characters.
- Side asks share `ask`'s counters: `ASK_PER_TURN` 10, `ASK_PARALLEL` 3, keyed by the owner's `turn`.
- B's side entry keeps `/btw`'s limits: `SIDE_MAX_OPEN` 3, `SIDE_TIMEOUT_MS` 180 000. A's side entry's clock pauses while a `side_question` call is in flight, capped at 360 000 ms overall.
- Every sentence A can read passes `SAFE_ASK_MESSAGE` (`/^[A-Za-z0-9 .,:;'(){}?@_-]{1,400}$/`). Nothing else (paths, CLI text, capabilities) ever reaches A.
- `SIDE_GUARD_SETTINGS` stays byte for byte as it is for every side run without the exception.
- No approval card, rule or Jev hint for `side_question`, in the main run or the side run.
- A chat Stop never stops side answers (unchanged `/btw` rule).
- **Do not commit.** The user commits by hand (global rule). Leave every change in the working tree.
- Comments stay short and say why, in the repo's style. Dependencies unchanged.

## Review Focus

1. A side run of an agent without our bridge (rooms, Zumi Bot, a server restart before `baseFor` learns `asks`) must not get the exception guard or the tool in its note. Task 1 and Task 5 test both sides.
2. A `tool_input` that contains the side tool's name must never get a blocked tool through. Task 1's probe calls Bash with that text in its command.
3. B's side entry stopped from the A→B panel while A's side run waits: A gets the stopped sentence, and A's link chip reads Stopped. Task 3 and Task 8 cover it.
4. The A→B chat is deleted while a side ask runs: A gets a fixed sentence, never a store error. Task 4 covers it.
5. A side ask whose answer is empty, or longer than `ASK_REPLY_MAX`: the empty sentence, or the cut note. Task 4 covers it.

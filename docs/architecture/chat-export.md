# Chat export

**Chat export (`shared/src/chatExport.ts`, `backend/src/core/export/`, `http/export.ts`, `components/ExportDialog.tsx`, `net/chatExport.ts`).** **Export…** in a chat or room row's menu (the sidebar's and Archived's) and **Export reply** beside an agent message open `ExportDialog`: Markdown (`.md`) or a web page (`.html`), **Include tool steps and errors** (off by default), and from a message **This reply** or **Whole chat**; **Download** saves the chosen format through a blob (the shell shows its save dialog), **Copy Markdown** always copies Markdown (`copyPending`, whose `ClipboardItem` takes the pending text so Safari keeps the click). The text comes from `GET /api/export/<chatId>?format&steps&item&tz` (behind the gate, GET/HEAD only), which reads the chat's stored items, so the whole history goes out, not the pages a tab loaded; it answers `text/plain` with nosniff, `no-store` and an attachment name (`exportFileName`: the title without path or control characters, 80 characters, ` (reply)` for a reply), never `text/html`, so the page only ever runs from the saved file. Errors reach the dialog as fixed sentences (`exportError`). **What goes in** (`buildExport`, pure): user messages ("You", or the asking agent in an A→B chat, with attachment names), agent replies (consecutive parts of one agent's reply join; with steps, the part after its steps carries no new header), answered `AskUserQuestion` cards as question and answer pairs and `ExitPlanMode` plans always; tool rows (`toolSummary`), errors and unanswered questions only with steps; never notices, approval cards, handoffs, vault cards, side questions, to-dos, dispatch entries, hidden versions or the chat's folder. A reply (`item`) is that agent's run of items between other speakers (`replyRange`); an id that is no agent message is a 404. Times are `YYYY-MM-DD HH:mm` in the page's zone (`tz`), else `AppSettings.timeZone`, else the server's. **Markdown** (`toMarkdown`): a `#` title, a who and when line, each message under `**Who** · time` with `---` between speakers, steps as a quoted list of inline code, and a code fence a message left open closed (`closeFences`) so it can't swallow the rest. **HTML** (`toHtml`, `exportHtml.ts`): one self-contained page with inline CSS (light and dark by `prefers-color-scheme`, `unicode-bidi: plaintext` per block), no script, and a CSP meta `default-src 'none'; style-src 'unsafe-inline'; img-src https:` plus `referrer` `no-referrer`. Each message is parsed as the chat parses it (GFM and math through `mdast-util-from-markdown`, the shared price rule `guardInlineMath` in `shared/src/mathGuard.ts`, which `remarkMathGuard` now wraps), raw HTML turned into text, `toHast` with a per-message `clobberPrefix` for footnote ids, then `hastToHtml` (`hastHtml.ts`), an allowlist serializer: only Markdown's own elements and a fixed set of attributes, a link kept only when relative or `http(s)`/`mailto`, an image only from `https`, everything else unwrapped or dropped. Math stays TeX in code and Mermaid stays a code block (the page loads no KaTeX or Mermaid). Steps fold under a `<details>`. Design: `docs/superpowers/specs/2026-11-12-chat-export-design.md`.

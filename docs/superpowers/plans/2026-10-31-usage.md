# Usage Page and Per-Chat Cost Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Record what every chat, room member and moderator call costs, estimate old chats from Claude's session logs, and show it on a Usage page (account menu) and a cost chip in every chat.

**Architecture:**
- **Exact records:** each run's `result` (stream-json for turns, `--output-format json` for the moderator) becomes an exact cost record. Records are appended to `usage-records.jsonl` and synced by id. User messages go in the same file as small records.
- **Estimates:** derived, never synced. Logged assistant messages of the sessions ZumiBot chats name, minus those an exact record covers, priced by a table in `shared`. They're cached per log file in `usage-estimates.json`.
- **Aggregation and UI:** the server aggregates on `usage:query` and broadcasts `usage:changed`. The page and the chip are React components over pure state helpers.

**Tech Stack:** TypeScript, Node 22, React 19, vitest, playwright-core e2e. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-10-31-usage-design.md`

## Global Constraints

- **Dependencies:** none added. Existing ones stay pinned to exact versions, and every workspace shares one version number.
- **Commits:** never commit. The user commits themself. Skip any "commit" habit; end each task with tests green and a short summary.
- **Comments:** short, and they say *why* (an ordering constraint, a race, a security reason), matching the surrounding code.
- **Labels:** every dollar figure is the API list-price equivalent, labelled "API estimate · USD". Estimated amounts are always marked as estimated, and a model with no price is "unpriced", never $0.
- **Jev:** OpenRouter cost is not recorded. Claude Code sessions no chat names are never read.
- **Session logs:** read as streams, line by line, from `~/.claude/projects` (the server's `home` + `.claude/projects`). Never load a whole log into memory, and never block startup or a reply on them.
- **Shrinking:** totals never drop because a chat was deleted, edited or forked.
- **New API methods:** each touches three places: `ZumiBotApi` in `shared/src/types.ts`, the handler in `backend/src/rpc/handlers.ts` (args checked there), and `frontend/src/net/api.ts`.
- **Frontend tests:** cover only pure modules in `frontend/src/state/`. There are no DOM tests.
- **Prices (USD per MTok), from the claude-api skill (cached 2026-10-06).** Cache writes are 1.25× input for 5 minutes and 2× input for 1 hour.

  | model | input | output | cache read | write 5m | write 1h | rules |
  |---|---|---|---|---|---|---|
  | `claude-fable-5-1` | 10 | 50 | 0.25 | 12.50 | 20 | |
  | `claude-opus-5-5` | 4 | 20 | 0.20 | 5 | 8 | fast ×2 |
  | `claude-opus-5` | 5 | 25 | 0.50 | 6.25 | 10 | fast ×2 |
  | `claude-sonnet-5-5` | 2 | 10 | 0.20 | 2.50 | 4 | |
  | `claude-sonnet-5` | 2 | 10 | 0.20 | 2.50 | 4 | |
  | `claude-haiku-5-5` | 0.10 | 0.50 | 0.01 | 0.125 | 0.20 | prompt > 100,000 tokens: 0.50 / 2.50 / 0.05 / 0.625 / 1.00 |
  | `claude-haiku-4-5` | 1 | 5 | 0.10 | 1.25 | 2 | |

  - **Model ids:** a date suffix (`-YYYYMMDD`) is stripped before lookup.
  - **Prompt size:** input + cache read + cache write of that one message.
  - **Fast mode:** `usage.speed === 'fast'` multiplies every rate by 2. This is my call; the skill only states input and output.

## Review Focus

These are the five inputs most likely to bite, each pinned by a test in its owning task:

1. **A session log being written while it's read:** the last line is partial. Expect it to be skipped, with the offset left before it so the next read picks it up (Task 4, `readLogMessages keeps a partial last line for later`).
2. **A crash mid-append leaves a broken line in `usage-records.jsonl`:** expect that line skipped and every other record kept (Task 3, `load skips a broken line`).
3. **`<synthetic>` model lines and models missing from the price table:** synthetic lines are ignored. Unknown models keep their tokens with `costUsd: null` and show as unpriced (Task 4 `readLogMessages ignores synthetic lines`, Task 1 `priceMessage returns null for an unknown model`).
4. **A chat deleted mid-turn, or later:** its cost record is still saved and still counted, labelled "Deleted chat" (Task 6, `a deleted chat keeps its cost as Deleted chat`).
5. **Day boundaries in the viewer's time zone:** a record at 23:30 UTC belongs to the next day in `Asia/Baghdad` (Task 6, `days follow the query time zone`).

### Task 5: Estimates

**Files:**
- Create: `zumi-bot-server/backend/src/core/usage/estimates.ts`
- Test: `zumi-bot-server/backend/tests/core/estimates.test.ts`

**Interfaces:**
- Consumes: `LogMessage` (Task 4), `CostRecord`, `ModelSpend` (Task 1).
- Produces:
  ```ts
  export interface SessionOwner { sessionId: string; chatId: string; agent: string; chatCreatedAt: number }
  export interface EstimateBucket { chatId: string; agent: string; hour: number; model: string; spend: ModelSpend } // hour = start of the UTC hour, ms
  export function estimate(owners: readonly SessionOwner[], logs: ReadonlyMap<string, readonly LogMessage[]>, exact: readonly CostRecord[]): EstimateBucket[]
  ```
  `logs` is keyed by session id, with all of that session's messages (main and subagent logs together).

The algorithm, which the tests pin:
1. **Covered set:** for each exact record with `sessionId` S and `window` [a, b], every message of S with `a <= at <= b` puts its id in `covered`.
2. **Assign the rest:** walk owners by `chatCreatedAt` ascending (ties broken by `chatId`), keeping a `seen` set of message ids. Skip a message whose id is in `covered` or `seen`. Otherwise add it to `seen` and to the bucket `(chatId, agent, hour, canonicalModel)`.
   - `cacheWrite` = 5-minute + 1-hour tokens.
   - `costUsd` sums, and becomes `null` once any message in the bucket is `null`.

- [ ] **Step 1: Write the failing tests:**
  - `estimate buckets by chat, agent, hour and model`: two messages in the same hour and model give one bucket with summed tokens.
  - `estimate skips messages inside an exact record's window`: an exact record for S with window [t1, t2] removes S's messages in that window and keeps those before t1.
  - `an exact record arriving later shrinks the estimate by the same amount`: compare `estimate` with and without the record. The difference equals the covered messages' tokens and cost.
  - `a fork copy of exact history counts nowhere`: S2 holds a copy of S1's `msg_1` (same id, in S2's file), and S1's exact window covers `msg_1`, so `msg_1` is in no bucket.
  - `a fork copy of estimated history goes to the chat created first`: `msg_1` in both S1 (chat A, created 1) and S2 (chat B, created 2) lands only in A.
  - `a session named by two chats counts once`.
  - `an unpriced message makes the bucket cost null but keeps its tokens`.

How each method behaves:
- **`start`:**
  1. `store.load()` and `cache.load()`.
  2. In the background, the message import: for every chat, `noteItems` its items and every user item in its versions file.
  3. Then the estimate pass: collect owners, `findSessionFiles`, then read each file from its cached offset. Re-read from 0 when the file shrank or the cache has none. Yield (`await setImmediate`) between files.
  4. Then `cache.save()`, set `estimating = false` and call `changed(null)`.
- **Owners** (every session id a chat names):
  - **Single chats:** `meta.sessionId` and every `end.session` / `cut.session` in its items and versions file, all with `agent = meta.agentName`.
  - **Rooms:** each `group.sessions[member]` with that member, and each `end.session` with `end.agent`.
  - **Sessions on exact records** whose chat is gone, with `agent` from the record and `chatCreatedAt = record.at`.
- **`recordRun`:** add a cost record (`at = window[1]`), recompute estimates in memory (no log read), then `changed(chatId)`.
- **`recordModerator`:** the same, with `agent: MODERATOR_AGENT`, `sessionId: null`, `window: null` and `id ?? randomUUID()`.
- **`noteItems`:** add `{ kind: 'msg', id: item.id, chatId, at: item.ts }` for each `type: 'user'` item whose id isn't held yet.
- **`refreshSession`:** re-read just that session's files from their offsets, recompute, save the cache, then `changed(chatId of that session)`.
- **`query`:** `summarize({ records: store.all(), estimates, chats: <current chat titles>, estimating, agentLabel }, q)`.
- **Handler:** `'usage:query'` checks `from`/`to` (finite number or null), `agent`/`chatId` (string or null) and `timeZone` (a string that `Intl.DateTimeFormat` accepts, otherwise `'UTC'`), then calls `d.usage.query`.
- **`agentLabel`:** `displayName` from `@zumibot/shared/frontmatter`, with `MODERATOR_AGENT` mapped to `'Room moderator'`.
- **Wiring in `app.ts`:**
  - `onRunCost: (e) => usage.recordRun(e)`
  - `onRunWithoutCost: (_chatId, sessionId) => usage.refreshSession(sessionId)`
  - `runModerator({ …, onCost: (c, id) => usage.recordModerator(chatId, c, id, Date.now()) })`
  - `changed: (chatId) => hub.broadcast({ event: 'usage:changed', payload: { chatId } })`

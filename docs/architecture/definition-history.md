# Saved history of workflows and routines

**Saved history of workflows and routines (`core/history/`, `shared/src/definitionHistory.ts`, `components/HistoryDialog.tsx`, `state/versionHistory.ts`).** Every save through `workflowEditing.save` and `routineEditing.save` (the editors' and Zumi Bot's tools alike) keeps the definition it saved: `workflowDef` (name, time zone, trigger, steps, edges, notes, groups) or `routineDef` (name, time zone, trigger, target, prompt, command, the three policies read with their defaults), never on/off, times or a webhook's `sample`, built key by key so two compare by JSON (`sameDef`). A save that changed nothing (an on/off switch) keeps nothing. When the history is empty or its newest version differs from the definition being replaced (saved before history existed, a Duplicate's copy, anything written around a save), that definition is kept first as an `earlier` version dated by its `updatedAt`. Each version has a `source`: `editor`, `zumi-bot` (AutomationService passes it), `restore` (with `restoredFrom`, the restored version's time, from the save's optional second argument `{restoredFrom}`) or `earlier`. `HistoryStore` writes one file per item, `<data>/history/workflows/<id>.json` and `<data>/history/routines/<id>.json` (`{v: 1, versions}`, newest first, an id checked by `HISTORY_ID_RE` before it is a path, a queue per item, a corrupt file moved aside), pruned to `HISTORY_KEPT` (50) versions within `HISTORY_CHARS_MAX` (2 000 000) characters, the newest always kept. A history write runs after the save landed, so its failure is logged by code only (`keepHistory`) and never fails the save. Deleting the workflow or routine deletes its file; an agent rename rewrites the kept definitions last in the pipeline (`renameWorkflowDef`, `renameRoutineDef`), caught and logged. RPCs: `workflows:history`/`routines:history` return `VersionSummary`s newest first (`summarizeVersions`: `current` when it equals the saved definition, `changes` against the one before, from `workflowChanges` such as "Step “Each” changed" or "Layout changed" when only places moved, or `routineChanges`), and `workflows:version`/`routines:version` one version's definition (`VERSION_NOT_FOUND` once pruned). **UI.** The ⋯ menu's **History…** (`wf-history`, `routine-history`; off for one never saved) opens `HistoryDialog` (`history-row` with `data-current`, `history-changes`, `history-restore` on every row but the current, `history-close`): when, who ("Saved by you", "Saved by Zumi Bot", "Restored from …", "Earlier version") and what changed. Restore loads the version as unsaved edits keeping the id and on/off (a webhook keeps the hook's latest call; `restoredWorkflow`, `restoredRoutine`) and says "Restored the version from … Save to keep it, or Discard changes to go back."; nothing is written until Save, whose version is then `restore`. In the workflow editor the restore is one undo step; the routine form has no undo, so over unsaved edits it asks first ("Replace your unsaved changes?"). Delete removes the history too, so a deleted item cannot be restored. Design: `docs/superpowers/specs/2026-11-12-foreach-concurrency-and-history-design.md`.

# Usage

**Usage (`core/usage/`).** Exact records come from run results: the `result` event's `uuid` and cost become a cost record (`runCost.ts`; the moderator's `--output-format json` call is recorded the same way), plus one user-message record per send. A resumed CLI restores the session's last `cost-state` line (written into the session log at the end of every run, and read from the source session for `--fork-session` and cut runs too) and adds the run to it, so a result's `total_cost_usd`/`modelUsage` are the whole session's so far. `costBaseline.ts` reads that line before the run spawns (main turns in `ChatService`, side runs in `sideRun.ts`) and `minusBaseline` leaves only the run's own cost; such records carry `v: 2`. Older session records (`wholeSessionCost`: a session id and no `v`) stored session totals, counting each turn's history again (about 5× too much), so they are left out and their sessions estimated from the logs instead, appended to `usage-records.jsonl` (`usageStore.ts`). Old chats and anything no exact record covers are estimated from the CLI's session logs under `~/.claude/projects` (`sessionLogs.ts`, `estimates.ts`: each message id counted once, minus the windows exact records cover), cached by file offset in `usage-estimates.json` and priced from the table in `shared/src/pricing.ts` (bump `ESTIMATE_VERSION` when it changes, so the cache is rebuilt). `sync.mjs` unions the records files by id and never copies the estimates cache. The UI asks with `usage:query` (summary for a range, agent or chat) and refetches on `usage:changed`; **Settings › Usage** shows the page (`UsageView.tsx`) and each chat's cost chip (`CostChip.tsx`) opens its breakdown and a link to the page filtered to that chat.

# Turn X-ray

**What it is.** One reply drawn as a timeline: each model request (tokens, cache, priced cost), the tool calls it asked for (run time, the card's wait on the user, the audit decision, the outcome), and each subagent's own requests and calls nested under its Agent call. A summary on top gives the wall clock, the exact cost, total tokens, cache share and a three-way split: **Model** (the agent's own requests), **Tools** (the rest) and **Waiting on you** (wall clock with at least one card open). Opened from an agent message's **Turn X-ray** button (`MessageActions`, `data-testid="xray-button"`; not in the island popup), it fills the side panel's `xray` view (`XrayPanel.tsx`, focus `{chatId, itemId, n}` in `App.tsx`). User page: `zumi-bot-docs/src/content/docs/chatting/turn-xray.md`.

**Nothing new is stored but one field.** The timeline is put together on each `xray:get(chatId, itemId)` from what already exists, and kept nowhere:

| Source | Gives |
| --- | --- |
| Chat items | the turn's tool rows (`ts`, `doneTs`, `blocked`, `isError`), approval cards (`ts`, status, and the new `answeredTs`), errors and Stop notices (the run's status), the `end` mark's session id |
| Dispatch file (`DispatchService.entries`) | each subagent's tool steps with times, nested dispatches (`agent` steps), its status, start and end |
| Audit log (`AuditLog.each({chatId, from, to})`) | the decision per call: a top-level call by `itemId` (its tool use id, no `parentToolUseId`); a subagent's by `parentToolUseId` and tool name in announce order (its records carry no tool use id), at most 20 000 records per ask |
| Usage records (`UsageStore.all()`) | the run's exact cost (`v: 2` cost records of this chat and agent whose window meets the turn) and its session id |
| CLI session logs (`~/.claude/projects/*/<session>.jsonl`, `<session>/subagents/agent-*.jsonl`) | each request: message id, model, first and last line time, usage (the line with the most output, since the CLI repeats it per content block), its `tool_use` ids and whether it wrote text or thinking (`xrayLogs.ts`) |

`answeredTs` is set once on an approval card when it stops waiting: answered, denied, skipped, sent back, cancelled, or closed `unanswered` at turn end (`setApproval`, `answerQuestions`, `answerPlan` in `chatService.ts`). Cards saved before it have none, and their calls read `waitUnknown`. Cards a rule or Auto mode let through as they were made (`auto-allowed*`) never waited and are not counted as cards.

**Which items are the turn** (`turnItems` in `xrayService.ts`): the asked agent message's speaker's run of items between other speakers (Export's reply rule), cut at `end` marks so a room member's two turns in a row stay apart; a hidden Run result (`user` with `run`) is skipped, as Export does. A room turn still running is taken by its `turn` stamp instead, since its items interleave with other members' until it ends. The item before it, when a user message, gives the send time. The turn is running when the chat is `inFlight`, no item has `end` and no later item is that agent's.

**The window.** Start: the earliest matching cost record's spawn (`window[0]`), else the user message's time, else the first item's. End: the latest of the items' times (`doneTs`, `answeredTs`) and the cost records' results; null while running. Logs and audit records are read 60 s around the items and trimmed by the builder: a request counts when it was logged inside the window (±2 s, `XRAY_LOG_SLACK_MS`) or names one of the turn's calls.

**Session logs.** Session ids: the `end` mark's, then the cost records', then the chat's current one (a running turn has neither). `findSessionFiles` finds them under any project folder. A subagent log is read only when its `.meta.json` names (`toolUseId`) one of the turn's dispatches, nested ones included; a log with no meta file (older CLIs) is read when touched since the window's start, and matched to a dispatch by a shared tool use id. Only lines containing `"assistant"` are parsed. Codex, ACP and AG-UI turns read no log (`engine` from the chat's `sessionEngine(s)`), so they show calls only, gap `noLog`.

**Steps** (`stepsOf` in `turnXray.ts`). Calls are grouped under the request whose `tool_use` ids name them. A request starts when the one before could hand back (its own last line, or its calls' latest result), the first at the run's start; it ends at its last logged line. Calls no request names get a request-less step at their own time; with no log at all every call goes into one such step, and the panel draws calls without request rows. Model time is the sum of the agent's own request spans; a subagent's time is inside its Agent call. Wait is the union of the cards' `[ts, answeredTs]` (a pending card of a running turn: to now). Tools is what is left of the wall clock.

**Cost.** Each request is priced from `shared/src/pricing.ts` (`priceMessage`); an unknown model leaves it unpriced (`totals.unpriced`). The header shows the cost records' sum when there is one (the run's own `total_cost_usd`, exact) and otherwise the priced requests' sum as an estimate; the counts line adds the priced sum next to an exact cost.

**Gaps** (`XrayGap`, shown as notes under the summary): `noLog` (no session log, or none of its requests fell in the turn), `waitUnknown`, `noAudit` (a finished call with no audit record: the cap dropped it, the run was on another machine, or no audit log here).

**Shapes.** `shared/src/xray.ts`: `TurnXray { run: XrayRun, totals, gaps }`, `XrayRun { steps: XrayStep[] }`, `XrayStep { id (message id or null), tokens, costUsd, calls }`, `XrayCall { card, cardStatus, waitMs, waitUnknown, decision, outcome, run (a subagent's XrayRun) }`. Outcomes: `ok`, `error`, `blocked` (denied, refused, skipped, sent back, unanswered, or an audit denial), `running`, `cut` (no result when the turn ended).

**Panel** (`XrayPanel.tsx`, pure rules in `state/xray.ts`, styles `styles/xray.css`). Fetches on open and every 2 s while the turn runs; bars of a running turn grow each second. The X-ray stays with its chat: on another chat the side panel shows its list, and going back shows the X-ray again. A row's title is the tool and what it did (`callLabel`, so the summary's own tool name is not said twice); a subagent's is its type and task. Rows: a request, then its calls one level in; a subagent's rows start folded under its Agent call (`xray-fold`). A call's bar runs from its start to its result, its card's wait drawn striped over the bar's start (only the answer time is kept, so the wait is placed at the call's start). Decision chips reuse the audit page's `audit-chip` and `decisionLabel`. DOM hooks: `xray-panel`, `xray-close`, `xray-retry`, `xray-gone`, `xray-summary`, `xray-live`, `xray-time`, `xray-cost`, `xray-tokens`, `xray-cache`, `xray-split`, `xray-counts`, `xray-gap` (`data-gap`), `xray-rows`, `xray-empty`, `xray-step` (`data-id`), `xray-call` (`data-id`, `data-tool`, `data-outcome`), `xray-wait`, `xray-fold`.

**Limits.** A long session log is read whole on every ask (one pass, assistant lines only); a running turn re-reads it every 2 s while the panel is open. A clock step between the CLI's log times and the server's item times shifts request bars against call bars. Vault approvals and browser handoff cards also wait on the user but are not drawn. A subagent's calls are matched to their audit records by order within each tool name, so two parallel calls of one tool in one subagent can swap decisions.

**Tests.** `backend/tests/core/turnXray.test.ts` (grouping, windows, waits, decisions, nested subagents, running turns, gaps, `turnItems`), `backend/tests/core/xrayLogs.test.ts` (block lines joined, window, synthetic and unpriced models, meta files), `frontend/tests/xray.test.ts` (rows and folding, bars, words and numbers).

# Unread markers and Archive

**Unread markers.** A chat is unread when `ChatMeta.replyAt` is later than `seenAt` (`shared/src/unread.ts`; a chat with no `replyAt` never is). `ReadMarks` (`core/chat/readMarks.ts`) sets both: `ChatService.onTurnEnd` for single chats, `GroupService`'s own `onTurnEnd` for rooms (a pass never marks; ChatService's hook skips rooms, since it fires before the pass is dropped), and presence `onStarted`/`onStopped`. A turn that ends while someone looks stamps both times; opening a chat marks it seen; looking away from a running chat marks what arrived so far. Its writes go through `ChatStore.patchInPlace`, so `updatedAt` (the sidebar order) never changes, and they never block a turn. `sync.mjs` keeps the later of each time, and its copy chats start read. The UI is `state/unread.ts`: a dot on chat and group rows, rolled up to a collapsed agent, a collapsed section, the drawer toggle and the rail's Agents button (an approval badge wins the slot), and a New line above the whole agent group holding the first unseen item, held from the chat's open so the server's read does not move it. **Mark unread** on an agent message (`chats:markUnread`, `ReadMarks.markUnread`) sets `ChatMeta.mark` `{at, from}` (`from` just before that message); the chat counts as unread while `mark.at > seenAt` (`markOn`), the New line shows above it at once, and the user stays in the chat. Only an open ends it: each presence report carries `openedAgoMs` (when that page opened the chat; a load counts) and `ReadMarks.opened` clears the mark when the open is later than `mark.at`. A look start, a look stop or a reply while looking never moves `seenAt` while a mark is on, so a refocus, an idle round or a reconnect keeps it. `sync.mjs` keeps the later mark, and copy chats start without one. Design: `docs/superpowers/specs/2026-11-02-unread-markers-design.md`.

**Archive.** Right-click (or long-press) a chat or room row → **Archive** (`chats:archive`, refused while the chat runs with `ARCHIVE_RUNNING`, checked inside `patchInPlace`). `ChatMeta.archivedAt`/`unarchivedAt` are both kept once set; archived while `archivedAt` is later (`shared/src/archive.ts`), each new time past the other even against a slower clock, and neither moves `updatedAt`. `ChatStore.updateLocked` unarchives whenever a patch sets `inFlight: true`, so a send, a routine run, a room turn or a compact always brings the chat back and no approval card hides in the archive. The client passes `liveChats(chats)` (`state/archive.ts`) to the sidebar and every unread roll-up; the sidebar layout is left alone, so a room returns to its stored spot. The rail's **Archived** button (`archived-open`) sets `archive` in `App.tsx`: `ArchivedNav.tsx` takes the sidebar's place (as Settings' nav does; the drawer on a phone) with search, a row menu (Unarchive, Delete) and ticks for several at once: each row's box sits over its icon (shown on hover, on every row once one is ticked; Shift-click ticks a range), ticking never opens the chat, and the bar over the list (`archived-bulk`) counts only the ticked rows the search shows and offers Select all, Unarchive and Delete (one confirm for all; deletes run one at a time). Pure rules in `state/archiveSelection.ts`; ticks live in the component, so leaving Archived drops them, the main area shows the chat opened from it with a note and **Unarchive** in `ChatView`'s top bar, and the address is `/archived` or `/archived/<id>` (`state/route.ts`). A notification or a `/chat/<id>` address closes it. `sync.mjs` keeps the later of each time. Archiving a worktree chat (and deleting one) also runs worktree release in the background and shows its outcome as a line in the archived note, see [Git worktrees](worktrees.md). Design: `docs/superpowers/specs/2026-11-04-chat-archive-design.md`.

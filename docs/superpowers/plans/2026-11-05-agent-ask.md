# Agent Asks Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** In a single chat, agent A can ask any other agent B through a ZumiBot tool. B runs in an "A → B" chat under B that the user can only read, and A gets B's final reply back.

**Architecture:** There is a new per-attempt MCP bridge, `zumibot_agents`, a copy of the `zumibot_todos` bridge pattern (an owned Unix socket plus a capability token). Calls go to an `AgentAsks` service. It checks the rules, finds or creates the A→B chat, and runs one ChatService turn of B through a new `ChatService.runAsked`. ChatService links each running A→B chat to the chat that asked it, so pending approvals roll up the chain and Stop cascades down it. In the UI, an A→B chat is read-only, and in A's chat an ask tool item renders as an ask card that holds B's pending cards.

**Tech Stack:** TypeScript, Node 22, `@modelcontextprotocol/sdk` (already a dependency), React 19, vitest, and playwright-core for e2e.

**Spec:** `docs/superpowers/specs/2026-11-05-agent-ask-design.md`

## Global Constraints

- **No git commits** unless the user asks (their global rule). Each task ends with a checkpoint run instead of a commit.
- Tool server name `zumibot_agents`. The agent sees the tool as `mcp__zumibot_agents__ask`, with input `{agent, message}` and no other keys.
- Message cap 20 000 characters, reply cap 50 000 characters (with a note when cut).
- Chain limit 3 hops: a call from an owner whose `chain.length >= 3` is refused.
- Per turn of the caller: 10 asks in total and at most 3 running at once.
- MCP config entry: `timeout: 86400000`. Bridge env: `CLAUDE_CODE_MCP_AUTO_BACKGROUND_MS: '0'`.
- No ask bridge and no ask paragraph for Zumi Bot (`ZUMI_BOT_NAME`), for room turns (`spec.author !== undefined`), or for the moderator, room summary and side picker (they already run with `--strict-mcp-config`).
- A's message and B's reply never go into logs, URLs or error text. Refusals are the fixed sentences in `askPrompt.ts`.
- Comments are short and say *why*. Dependencies stay pinned, and no new dependencies are added.
- Frontend logic lives in pure `src/state/` modules with tests. Components hold no logic worth testing.

## Review Focus

1. **Handles typed in any case or with `@`** (`@Workiom-Master`, ` workiom-master `): they resolve to the agent. An unknown handle is refused with the list of real handles. Test in Task 1.
2. **B renamed between two asks from the same chat**: the second ask continues the same A→B chat (the rename moved `agentName`), and `asked.by` and the `from` fields follow a rename of A. Test in Task 5.
3. **Deleting A's chat, or the A→B chat, while B works**: the chain stops, A's call ends with the "stopped" sentence, and nothing stays `inFlight`. Test in Task 4.
4. **B's turn ends with only tool calls, or with a 200 000-character reply**: A gets "@B finished without writing a reply." or the reply cut at 50 000 characters with the cut note. Test in Task 3.
5. **Stop while B waits on an approval shown in A's chat**: both turns stop, the card turns `unanswered`, and the pending counts of both chats drop to 0. Test in Task 4.

Copy `core/todos/todoIpc.ts` and keep the same hardening:
- an owned `mkdtemp('/tmp/cb-a-')` directory, 0700
- a 0600 socket
- the auth line within 5 s
- `requestLimit` 65536 (it fits a 20 000-character message, even all multi-byte), `responseLimit` 1 MiB (fits the 50 000-character reply), `pendingLimit` 4

Two differences from the todo IPC:

1. **Cancel.** `run` sends `{type: 'cancel', id}` when its signal aborts, the same way `BrowserIpcClient.run` does. On the server, each request gets an `AbortController`, which is aborted by a `cancel` message, by the socket's `close`, and by `dispose()` of its token. That abort is what stops B when A's CLI dies.
2. **Config.** `createAskTurn` puts `timeout: 86400000` on the `zumibot_agents` entry and returns `env: { ZUMIBOT_ASKS_CAPABILITY: token, ZUMIBOT_ASKS_IPC: socketPath, CLAUDE_CODE_MCP_AUTO_BACKGROUND_MS: '0' }`.

The token never appears in argv. Error text that reaches the bridge goes through the `SAFE_MESSAGE` filter, the same one `todoIpc.ts` uses, except the length limit is 400 so that the unknown-agent sentence with its handle list fits. Text that fails the filter becomes `Agents unavailable`.

`askBridge.ts` mirrors `todoBridge.ts`:
- It reads and deletes `ZUMIBOT_ASKS_CAPABILITY` and `ZUMIBOT_ASKS_IPC`.
- It passes the SDK handler's `extra.signal` to `ipc.run`.
- It returns `{content: [{type: 'text', text}]}`, or `isError: true` with the message.

### Task 3: The `AgentAsks` service and prompts

**Files:**
- Create: `zumi-bot-server/backend/src/core/asks/askPrompt.ts`, `askService.ts`
- Test: `backend/tests/core/askPrompt.test.ts`, `backend/tests/core/askService.test.ts`

**Interfaces:**
- Consumes: Task 1 constants and helpers; `AskOwner`, `AskCall` (Task 2); `ChatService.runAsked` (Task 4; faked in this task's tests).
- Produces:
  - From `askPrompt.ts`:
    - `askSystem(roster: { name: string; description: string }[]): string`. This is the fixed paragraph from the spec's "What A is told", followed by a `Agents you can ask:` list of `- @name: first line of description`. It returns `''` when the roster is empty.
    - `askedSystem(by: string, fromTitle: string): string`. This is B's paragraph from the spec's "The A→B chat".
    - `QUESTIONS_DENIED(by: string): string`. Returns `` `Ask your question at the end of your reply; @${by} will answer or ask the user.` ``
    - `REFUSAL`: a frozen object of the fixed sentences, keys `unknown(handles: string[])`, `zumiBot`, `self`, `inChain(name)`, `tooDeep`, `perTurn`, `parallel`, `busy(name)`, `broken(name)`, `limited(name, resetsAt: number | null)`, `failed(name)`, `stopped(name)`, `stopping`, `noText(name)` (returns `` `@${name} finished without writing a reply.` ``), `cut` (returns `'\n\n[Reply cut at 50000 characters.]'`)
  - From `askService.ts`:
    - `class AskRefusal extends Error {}`
    - ```ts
      interface AgentAsksDeps {
        agents(): Promise<AgentSummary[]>
        chats: Pick<ChatStore, 'list' | 'get' | 'create' | 'update'>
        run(chatId: string, o: { from: string; message: string; chain: string[]; parent: string; signal: AbortSignal }): Promise<AskedOutcome>
        push(p: ChatPush): void
      }
      ```
    - `type AskedOutcome = { kind: 'ok'; reply: string | null } | { kind: 'busy' } | { kind: 'stopped' } | { kind: 'limited'; resetsAt: number | null } | { kind: 'error' }`
    - `class AgentAsks { constructor(d: AgentAsksDeps); ask(owner: AskOwner, call: AskCall, signal: AbortSignal): Promise<string>; endTurn(turn: string): void; close(): void }`

What `ask` does, in order. Every refusal throws `AskRefusal(REFUSAL.x)`.
1. Resolve the target with `findAskTarget` over the loadable agents (`error === null`). Refuse in this order:
   - unknown → `unknown` (with the sorted handles, minus Zumi Bot and the caller)
   - Zumi Bot → `zumiBot`
   - the caller itself → `self`
   - a name in `owner.chain` → `inChain`
   - `owner.chain.length >= ASK_MAX_HOPS` → `tooDeep`
   - 10 asks already counted for `owner.turn` → `perTurn`
   - 3 running for `owner.turn` → `parallel`
   - `closed` → `stopping`
2. Find the A→B chat: `chats.list()`, the first with `asked?.from === owner.chatId && agentName === target.name`. If there is none, `create(target.name, sourceMeta.cwd)` and then `update(id, {asked: {by: owner.agent(), from: owner.chatId, fromTitle: source.title, chain: [...owner.chain]}, title: askedTitle(...)})`, and push the meta. If the source chat is gone, refuse with `stopped`.
3. Count the ask, then `await d.run(id, {from: owner.agent(), message: call.message, chain: [...owner.chain, owner.agent()], parent: owner.chatId, signal})`.
4. Map the outcome:
   - `ok` with text: return it, cut to `ASK_REPLY_MAX` with `REFUSAL.cut` appended
   - `ok` with `null`: `noText`
   - `busy`: `busy`
   - `stopped`: `stopped`
   - `limited`: `limited`
   - `error`: `failed`
   - a missing agent file at run time: `broken`

`endTurn(turn)` forgets that turn's counters.

- **The ask bridge per attempt.** Create it in `attempt`, next to `todoTurn`, only when `this.d.askTurns && spec.author === undefined && spec.agentName !== ZUMI_BOT_NAME`. - **`permissionRequest`.**
  - `ownAsk(name)` (a bridged attempt and `name === ASK_TOOL`) gets `reply(allowResponse(...))`, with no card and no rule, the same as `ownTodo`.
  - When `spec.questionsDenied` is set and `e.toolName === QUESTION_TOOL`, the turn sends `reply(denyResponse(e.requestId, spec.questionsDenied))`, with no card.
- **Roll-up.**
  - Keep `private askParents = new Map<string, string>()` (child chat id → parent chat id).
  - `pendingCount(id)` is the chat's own pending plus `pendingCount(child)` for each child whose parent is `id`.
  - `pushApprovals` becomes `this.pushPending(chatId, agent)`. It pushes `{chatId, kind:'approvals', pending: pendingCount(chatId), agent, ...(askParents.has(chatId) ? {asked: true} : {})}`, then walks up `askParents` and pushes each ancestor's total with the same `agent`, without `asked` on the root.
- **Cascade.** `stop(id, reason)` also calls `stop(child, reason)` for every child whose parent is `id`.
- **`runAsked`.**
  - Claim the chat. If `claim` throws, return `{kind:'busy'}`.
  - Set `askParents` (child → `o.parent`), and abort-listen on `o.signal` with `this.stop(chatId)`.
  - Record a `user` item `{from: o.from, text: o.message}` and run the existing `runTurn` path, with a new optional `extra?: Pick<TurnSpec, 'systemPrompt' | 'askChain' | 'questionsDenied'>` set to `askedSystem(o.from, meta.asked.fromTitle)`, `o.chain` and `QUESTIONS_DENIED(o.from)`.
  - In `finally`, delete the link, remove the listener, push the parent's pending again, and release.
  - Return:
    - `stopped` when the turn stopped
    - `limited` with `resetsAt` when the last item is an error with `limit`
    - `error` for any other error
    - otherwise `ok`, with the text of the last `assistant` item after the recorded user item (`null` if there is none)
- **`onTurnEnd`.** For a chat with `asked`, pass `asked: true` in the `TurnEnd`. `runTurn` already loads the meta, so read the flag from it.

# Inbox Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A rail **Inbox** page that lists every card waiting on the user (tool approvals, questions, plans, workflow approvals, desktop/browser handoffs), answerable in place, plus a kept history of workflow Notify messages the user can archive or delete.

**Architecture:** The Waiting section is derived on the client from state the app already has (per-chat pending counts, each pending chat's loaded items) plus one small new RPC for waiting workflow Approval visits. Notify messages get a new server store (`workflow-messages.json`) written by the workflow runner before the push, served by `inbox:*` RPCs, joined by `sync.mjs`. Today's cards (`ApprovalCard`, `QuestionCard`, `PlanCard`, `ApprovalBox`) are reused inside a thin `InboxCard` frame.

**Tech Stack:** TypeScript, Node 22 server (hand-wired services, WebSocket RPC), React 19, vitest, playwright-core e2e with the fake claude.

**Spec:** `docs/superpowers/specs/2026-11-07-inbox-design.md` (read it with this plan; goal numbers below refer to it).

## Global Constraints

- **No git commits.** The user's global rule: never commit unless explicitly asked. Each task ends at a checkpoint (tests + typecheck green), not a commit.
- Node >= 22, npm workspaces, run everything from the repo root. No new dependencies.
- A new RPC touches three places: `ZumiBotApi` in `zumi-bot-server/shared/src/types.ts`, the handler in `backend/src/rpc/handlers.ts` (checks every argument with `str()` etc.), the mapping in `frontend/src/net/api.ts`. A new server event is added to the event union in `shared/src/rpc.ts`.
- Frontend tests cover only pure modules (`frontend/src/state/`, `frontend/src/net/`, `frontend/src/sw/` helpers); keep logic out of components.
- Message title/body never go into logs, URLs, error messages or broadcast events. Ids may.
- `workflow-messages.json` is written 0600 through `writeFileAtomic`.
- Pushes are unchanged: the Inbox counts as looking at no chat (spec non-goal, **user**). Presence and read marks are untouched.
- Values from the spec: keep newest **500** messages; tombstones kept **365 days**; Undo toast **6 s**; Notify title/body already cut to **80 / 200** by the runner.
- Comments are short and say *why*, in the repo's style.
- Bell sits between **To-dos** and **Archived** on the rail.

## Review Focus

1. **A Notify step with a blank title** — the push uses the workflow's name; the stored message must hold that same fallback, not an empty title. Test: Task 2 `stores the fallback title the push used`.
2. **A room's card** — the header must name the member that asked (`item.agent`), not the room. Test: Task 6 `header names the room member`.
3. **A chat deleted or not listed while its card shows** — its cards must leave the stream and the badge. Test: Task 6 `drops cards of chats no longer listed`.
4. **A message whose run was pruned or workflow deleted** — Open run → is hidden, the message stays. Test: Task 6 `hides Open run when the run is gone`.
5. **Reconnect while cards wait** — handoffs must count again after `resyncApprovals`. Test: Task 8 `pendingFromItems counts pending handoffs`.

**Interfaces:**
- Produces (`shared/src/inbox.ts`):
  ```ts
  export interface WorkflowMessage {
    id: string            // the Notify visit's id, so a second add of the same visit is a no-op
    workflowId: string; workflowName: string; runId: string; stepName: string
    title: string; body?: string
    at: number            // when the step fired
    archivedAt?: number
    deletedAt?: number    // tombstone; title/body are emptied once STRIP_AFTER_MS passed
    updatedAt: number     // bumped by archive, unarchive, delete, restore: sync's per-message winner
  }
  export interface WorkflowMessagesFile { v: 1; seenAt: number; messages: WorkflowMessage[] }
  export interface InboxMessages { messages: WorkflowMessage[]; seenAt: number } // tombstones left out
  export type NewWorkflowMessage = Omit<WorkflowMessage, 'archivedAt' | 'deletedAt' | 'updatedAt'>
  export const INBOX_KEPT = 500
  export const TOMBSTONE_KEEP_MS = 365 * 86_400_000
  export const UNDO_MS = 6_000
  export const STRIP_AFTER_MS = 60_000 // server-side slack over the 6 s toast
  export function pruneMessages(f: WorkflowMessagesFile, now: number): WorkflowMessagesFile
  export function isNewMessage(m: WorkflowMessage, seenAt: number): boolean // m.at > seenAt && no archivedAt/deletedAt
  ```
  `pruneMessages`: strip title/body (`title: ''`, no `body`) from tombstones older than `STRIP_AFTER_MS`; drop tombstones older than `TOMBSTONE_KEEP_MS`; keep the newest `INBOX_KEPT` non-deleted by `at` (tombstones don't count).
- Produces (`workflowMessages.ts`):
  ```ts
  export const MESSAGE_NOT_FOUND = 'Message not found'
  export const TOO_LATE = 'Too late to undo'
  export class WorkflowMessages {
    constructor(dataDir: string, now: () => number)
    add(m: NewWorkflowMessage): Promise<boolean>  // false when the id exists (tombstone included)
    has(id: string): Promise<boolean>
    list(): Promise<InboxMessages>
    setArchived(id: string, on: boolean): Promise<void>
    remove(id: string): Promise<void>             // tombstone
    restore(id: string): Promise<void>            // Undo; TOO_LATE once stripped
    markSeen(at: number): Promise<void>           // never moves seenAt back
  }
  ```
  Same queue/read/write shape as `core/voice/voiceStore.ts`; file `workflow-messages.json`; every write runs `pruneMessages`; a missing or unreadable file reads as `{v:1, seenAt:0, messages:[]}`.

### Task 6: Pure Inbox rules

**Files:**

**Interfaces:**

- Produces:
  ```ts
  type ApprovalItem = Extract<ChatItem, { type: 'approval' }>
  type HandoffItem = Extract<ChatItem, { type: 'browser-action' }>
  export type WaitingEntry =
    | { kind: 'card'; key: string; chatId: string; item: ApprovalItem; since: number }
    | { kind: 'handoff'; key: string; chatId: string; item: HandoffItem; since: number }
    | { kind: 'workflow'; key: string; approval: WorkflowApproval; since: number }
  export function chatsToLoad(pendingByChat: Record<string, number>): string[]
  export function waitingEntries(o: {
    chats: readonly ChatMeta[]; pendingByChat: Record<string, number>
    itemsOf: (chatId: string) => readonly ChatItem[] | undefined; approvals: readonly WorkflowApproval[]
  }): WaitingEntry[]                                   // oldest `since` first, then key
  export function countText(n: number): string | null  // null at 0, '99+' above 99
  export function waitedText(since: number, now: number): string // 'just now' | 'waiting N min' | 'waiting N h' | 'waiting N d'
  export function entryHeader(e: WaitingEntry, chats: readonly ChatMeta[]): { who: string | null; where: string; link: 'chat' | 'run' }
  export interface AnsweredLine { key: string; since: number; text: string; until: number }
  export function answeredText(e: WaitingEntry, reply: ApprovalReply | 'approved' | 'rejected' | 'done' | 'cancelled'): string
  export type InboxRow = { kind: 'entry'; entry: WaitingEntry } | { kind: 'answered'; line: AnsweredLine }
  export function inboxRows(entries: readonly WaitingEntry[], answered: readonly AnsweredLine[], now: number): InboxRow[]
  export type InboxFilter = 'all' | 'waiting' | 'messages'
  export function messageView(m: InboxMessages, heldSeenAt: number, runs: WorkflowsSnapshot): {
    shown: Array<WorkflowMessage & { isNew: boolean; runGone: boolean }>     // not archived, newest first
    archived: Array<WorkflowMessage & { runGone: boolean }>                   // newest first
    newCount: number
  }
  export function anyNewMessage(m: InboxMessages | null): boolean
  ```
  Rules: `waitingEntries` reads only listed chats with pending > 0 and loaded items; a card is an `approval` item with status `pending`, a handoff a `browser-action` whose `handoff.status` is `pending`; keys are `chatId:itemId` / `run:visitId`.

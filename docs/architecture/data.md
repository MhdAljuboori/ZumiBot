# Data folder

**Data.** `ZUMIBOT_DATA_DIR`, default `~/.local/share/zumibot`. It holds `chats.json` (each chat's meta; `channel` (`{platform}`, Telegram or Slack, whichever linked it last) marks the current chat of a paired channel conversation, a sidebar mark only (see [Channels](channels.md)); `voice: true` marks a chat a voice request made (`chats:createVoice`), which only shows a mic mark in the sidebar, see [Voice conversations](voice-conversations.md); `worktree` (a `ChatWorktree`) marks a chat or room that runs in a git worktree ZumiBot made, see [Git worktrees](worktrees.md); `attempt` marks a chat as one of a card's parallel attempts and holds how its last turn ended, see [Review loop](review-loop.md); `pr` holds the GitHub pull request opened from the chat's worktree branch and the checks last read for it (volatile, never worth more than the next read), see [Review loop](review-loop.md); `allowRules` holds the `Bash(<prefix>:*)` and `Read(//<folder>/**)` rules the user granted for this chat from a blocked row, see [Allow a refused call](chat-mode-and-effort.md#allow-a-refused-call); `suggested` (`{after, options, question?, summary?}`) holds the suggested replies read for the reply ending at item `after`, see [App shell UI](ui.md); `sessionEngine: 'codex'` marks a `sessionId` that is a Codex thread (`'acp'` an ACP agent's session, `'ag-ui'` a remote agent's thread id, minted by ZumiBot), and a room's `GroupInfo.sessionEngines` each member's, see [Codex agents](codex.md) and [Protocol engines](protocol-engines.md)), `chats/<id>.json`, `chats/<id>.versions.json` (the hidden versions of edited messages), `chats/<id>.btw.json` (side questions and answers, kept apart from chat items and synced by entry id), `chats/<id>.agui.json` (a remote (AG-UI) agent's thread, 0600: `{v: 1, threadId, state, interrupts: [{id, expiresAt}]}`, the state the server last sent (null once a patch failed or it passed 256 KiB, then sent as `{}`) and the interrupts still open (kept before their cards wait, so after a Stop the next send cancels them); read only for its own `threadId`, so an Edit, Resend or Fork starts at `{}`; removed with the chat; `sync.mjs` brings it with a chat whose items come from the VPS and never gives one to a copy chat, which starts a new thread; see [Protocol engines](protocol-engines.md)), `todos.json` (the task board: every to-do, wherever it was made, each naming its creator chat; 0600, tombstones never pruned, synced by item id; a card's `attempts` holds a set of parallel attempts, see [Review loop](review-loop.md); a card's `pr` is the board's display copy of its task chat's pull request; a chat's own `chats/<id>.todos.json` from before the board is moved onto it at the next start and removed; see [To-dos](todos.md)), `attachments/todos/` (the board cards' images; synced like attachments), `vault.json` (the encrypted vault, 0600, each item sealed alone, tombstones never pruned, synced by item id; see [Vault](vault.md)), `settings.json` (with `theme`, `accent` (the color theme, see [App shell UI](ui.md)), `suggestedReplies` (the Suggested replies switch, on unless `false`, see [App shell UI](ui.md)), the `timeZone` the page last reported, see [Zumi Bot automations](zumi-bot-automations.md), and `worktreeFolders`, the repos whose "Isolate in worktree" toggle is on, synced inside `settings.json` with newest winning, see [Git worktrees](worktrees.md)), `connectors.json` (0600, through `writeFileAtomic`: each Claude agent's list of switched-on claude.ai connectors by catalog id, and `migration`, how the first-start switch-over ended, `kept` or `failed`, and `remember`, the services whose write calls run without a card in a chat (`{ "gmail": true }`: per service, not per agent, catalog ids only, absent means off, any other entry is dropped on read; a missing field reads as none and a corrupt file resets it); an agent with no entry has every connector off; holds no secret, since on route A the tokens stay at claude.ai; synced newest-wins; an unusable file is moved to `connectors.json.corrupt-<ms>`; see [Connectors](connectors.md)), `sidebar.json` (the user's sidebar sections and order, shared by every device; `core/store/sidebarStore.ts`), `usage.json`, `approvals.json` (remembered approvals by agent; a rule with `cli` set is a Claude Code allow rule made from a blocked row, see [Allow a refused call](chat-mode-and-effort.md#allow-a-refused-call)), `protocol-launch.json` (0600, the ACP launches and remote endpoints confirmed by Agent Studio's Save on this machine, by agent name: `provider: 'acp'` with `command`, `args` and `authEnv`, or `provider: 'ag-ui'` with `endpoint`, `authKey` (an env name, never a key) and `authHeader`, all of which the agent file already holds in plain text; per machine on purpose, never synced (`sync.mjs` excludes it), moved by the agent-rename pipeline and dropped with the agent; see [Protocol engines](protocol-engines.md), Launch trust), `routines.json`, `routine-runs.json`, `routine-hooks.json`, `workflows.json`, `workflow-runs.json`, `workflow-hooks.json` (0600, webhook secrets; like `routine-hooks.json` never copied by `sync.mjs`), `history/workflows/<id>.json` and `history/routines/<id>.json` (each item's saved versions, see [Saved history](definition-history.md); pulled from the VPS with the definitions), `workflow-messages.json` (0600, the Inbox's workflow Notify messages and its `seenAt`, tombstones kept a year; synced by message id), `jev.json`, `voice.json` (0600, holds the OpenRouter key and the `talk` settings: switch, default agent and spoken aliases (an old file's `ttsVoice` is ignored, and dropped on the next write), and the `clean` switches: filler cut and AI rewrite, both off by default; never synced, `sync.mjs` leaves it on each machine), `channels.json` (0600: per platform, Telegram and Slack, where the bot runs, the paired account, the agents allowed from it, Slack's shared-channel cards switch, and which notifications also go to the paired chat (`notify`, all off by default); no secret; the PC's copy comes from the VPS with `run` off; see [Channels](channels.md)), `channel-state.json` (0600, per machine, never synced, one entry per platform: Telegram's update offset, each conversation's current chat, which bot message is which chat, replies still streaming, card messages with buttons and recently run commands), `channel-tokens.json` (0600, per machine, never synced: each platform's tokens (Slack's bot and app-level token) sealed under the vault key, so they need the vault key file to open), `notify-devices.json` and `notify-vapid.json` (both 0600; devices hold push subscriptions and bound session keys; never synced), `spend-caps.json` (each capped agent's day: the limit Allow more today raised it to and whether its cap already tripped; per machine, never synced, see [Spend caps](spend-caps.md)), `usage-records.jsonl` (exact cost records and user-message records, synced by id), `usage-estimates.json` (derived cache, never synced), `attachments/`, `file-snapshots/<chatId>/<sha256>` (whole-file copies for the Files panel; folders 0700, files 0600, since an agent may have edited a `.env`; synced like attachments), `browser-shots/<chatId>/<name>.png` (the agent browser's saved screenshots, see [Browser audit tools](browser.md): folders 0700, files 0600, PNG, at most 200 files per chat and 5 MiB each, deleted with the chat, never synced, not copied by Fork or Clone room), `desktops/` (computer use: `profiles.json` and each agent desktop's `<profileId>/home`; never synced), `pause-flags/<hash>/` (0700, server-written only: the chat's pause flag, see [Pause and Resume](pause-resume.md); swept with `claude-tmp`), `claude-tmp/<hash>/` (each chat's `CLAUDE_CODE_TMPDIR`, `<hash>` the first 16 hex of the chat id's SHA-256, shorter than the id; `<data dir>/claude-tmp/<hash>/claude-<uid>/…` can still pass the CLI's ~104-byte unix socket limit with a long data dir or user name, which CLI 2.1.317 survives: sandboxed Bash falls back to another `$TMPDIR` with a debug warning, and only its `[uds-messaging]` socket, which ZumiBot does not use, fails to start when `XDG_RUNTIME_DIR` is unset; 0700, made before every CLI run of the chat: turns, room members, routines, A→B asked runs, Compact and side runs, which use their base chat's so the env matches; never the moderator or the room summary. It keeps the CLI's scratchpad and task output across a reboot, which `/tmp` would lose, and holds the pause flag. Deleted with the chat; at start the folders of chats that no longer exist are swept, never when the chat list reads empty; never synced), `audit/` (the audit log: one record per tool call of every run, `audit-<time>.jsonl` files 0600 in a 0700 folder, rotated at 16 MiB, whole oldest files dropped past the cap in `audit/cap.json`; denied to agents by the vault guard; never synced, not in a backup; it also holds `isolation.json`, each agent's isolation level, network list and extra folders (0600, written only by `isolation:set`, so the same guard keeps agents off it); see [Governance](governance.md)), `processes/` (background processes, see [Background processes](processes.md): `index.json`, 0600, every record running and ended, with each one's pid, boot id and `/proc` start time, which never leave the server; `<chatId>/<id>.log` and one older `<id>.log.1`, at most 2 MiB each, folders 0700, files 0600; the newest 20 ended records per chat and 200 MiB of logs in all are kept; deleted with the chat; per machine, never synced or backed up by `sync.mjs`, since pids and paths mean nothing on the other one) and `auth.json`. The vault key is not in it: it sits at `~/.config/zumibot-vault/vault.key` (`ZUMIBOT_VAULT_KEY_FILE`, refused inside the data dir or in a shared folder), so no copy or backup of the data dir carries it, and only `npm run sync`'s key step moves it between machines. Container isolation keeps each contained chat's fake home outside the data dir, at `~/.local/state/zumibot-containers/<owner>/<chatId>/home` (`<owner>` the first 12 hex of the data dir's SHA-256; 0700; the folders of chats that no longer exist removed at start; never synced; see [Governance](governance.md) 2.4). In Local mode, the first start with an empty data dir copies the old desktop app's data from `ZUMIBOT_MIGRATE_FROM` (`~/.config/ZumiBot`) and never changes the source (`migrate.ts`).

**Update files.** `update.json` (the self-update's `pending` and `lastResult`), `update-log.txt` (the last updater run's output, truncated each run) and `update-rolled-back` (`{"from","to"}`, written by `zumibot-rollback` and removed at the next start, which turns it into a rolled-back result). An `update-token.json` from an earlier version (a sealed GitHub token the updater no longer uses) is deleted at start. Beside the data dir, in the install dir (`~/zumibot`): `updates/` (downloads, cleared at every boot), `data.prev` (the snapshot an update keeps for a rollback, with `.zumibot-from`) and `app.prev`; after a rollback also `app.failed` and `<data>.failed`. Per machine (`sync.mjs` names none of them). See [Updates](updates.md).

**Workflow mail state.** `workflow-mail.json` (0600, through `writeFileAtomic`, per machine, never synced or copied) holds each enabled email-trigger workflow's place in its mailbox, `{<workflowId>: {key, uidValidity, lastUid}}` with `key` = `host|username|folder`; a different key or UIDVALIDITY starts over from the mailbox's next UID, and a workflow turned off or deleted loses its entry (see [Workflows](workflows.md), Triggers).

**Rename from ClaudeBot.** Before 0.1.0 the app was ClaudeBot. At start, `backend/src/legacyName.ts` renames `~/.local/share/claudebot` and `~/.config/claudebot-vault` to their `zumibot` names when only the old folder exists and the setting is unset or the default, and logs the names (never values) of any `CLAUDEBOT_*` settings still set, which are ignored. The vault keeps its `claudebot-vault` sealing labels (`vaultCrypto.ts`, `vaultSync.mjs`) so old items still open. `OLD_BUILT_IN_NAMES` moves the `claude-bot` agent to `zumi-bot` the way `bot-father-agent` moved. The desktop shell copies `server.json`, `island.json`, `window-state.json` and `sync.env` from `~/.config/ClaudeBot` once (`zumi-bot-desktop/src/main/legacyName.ts`), never moving that folder, which the previous app still uses. The old app keeps `~/.config/ClaudeBot`. The migration of old folders and the `claude-bot` agent lives in `legacyName.ts` (backend and desktop) and `OLD_BUILT_IN_NAMES`.

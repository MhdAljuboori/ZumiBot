# Thinking

**What the CLI sends.** A `-p` run of claude 2.1.322 streams every thinking block empty: `thinking_delta` lines carry only an `estimated_tokens` count, and the block's `assistant` line has `thinking: ""` and a signature. The hidden flag `--thinking-display summarized` (not in `--help`; it also takes `omitted` and `highlights`) makes the deltas carry the API's summary of the thinking as it streams, and the block's line the whole summary. The documented `showThinkingSummaries` setting does nothing in `-p` mode (passed through `--settings`, the blocks still came empty). The summary costs nothing extra: thinking is billed on its full tokens either way. A block's `assistant` line comes before any text of its request streams.

**Asking the CLI (`core/chat/thinkingDisplay.ts`).** An older CLI refuses an unknown option, which would fail every turn, so `createThinkingProbe` asks each binary once: `claude -p --thinking-display summarized` with stdin closed stops before any request (no prompt), and its error names the flag only when the CLI does not take it (an unknown option, or a value it no longer allows). Any output that does not mention the flag is a yes; one that does, a spawn error or a run past 15 s is a no. The answer is kept per binary path and its `mtime`/size, so an update is asked again. `app.ts` builds it over the run env, and `ChatService` asks it on each attempt of a Claude run (never Codex), after locate has readied that env; a no or a failed check leaves the flag out and chats show no thinking, as before.

**Args.** `buildArgs`' `thinking` adds `--thinking-display summarized` after the output flags. The side base keeps `thinking` in its `args`, so side questions and keep-warm pings (side runs) pass the flag alike: every run on a session sends the same thinking settings, since a change there may cost the session its prompt cache. The moderator, room summaries, the side picker and workflow bare calls are calls of their own and pass nothing.

**Parsing and storing.** `streamParser` turns a main-thread `thinking_delta` with text into `thinkingDelta`, and a non-blank `thinking` block into `thinking` (a `redacted_thinking` block, an empty one and a subagent's are dropped). `ChatService` pushes each `thinkingDelta` as a `delta` push with `thought: true` (and the room member's `agent`), and keeps each `thinking` as a chat item `{ type: 'thinking', text, ts, doneTs }`: `ts` is when its first delta came (else its end), `doneTs` when the block ended. The item is pushed with `clearStreaming`, which clears the live thought it replaces. Vault values are scrubbed from both, a value split across two deltas too: thought deltas get a `DeltaScrubber` of their own beside the reply's, flushed before the block and the result, and the item goes through `scrubEvent` like every event. A stop mid-thinking keeps nothing of it. Codex runs get no flag; see Codex below. In a room, a member's pass drops its thinking with its tool rows (kept with them when the turn asked for an approval). Search, export, the automations transcript, the seed prompt and what room members read of each other's turns leave thinking out.

**UI.** `chatView` keeps the live thought apart from the live text: `thought` for a single chat, `thoughtBy` per room member, cleared with that agent's live text by an items push that clears it. `foldTools` folds thinking items into the tool run around them, so a run reads "Thought for Xs" for what it holds and a lone thought makes a run of its own; a group ending in thinking is still at work (`endsInToolItems`). While a run spins ("Thinking…") or the working line shows, `thoughtPreview` puts the latest paragraph of the live thought beside it in one cut line (`live-thought`), and the working line then reads "Thinking…" instead of "Working…". An opened run lists each kept thought as `ThoughtRow` (`thought-row`): "Thought for Xs" (`thoughtTitle`, just "Thought" without both ends) over its first paragraph dimmed, opening to the whole summary as Markdown. A room's live block gets its member's `thoughtBy` and its thinking items (`liveTurns`).

**Codex.** A Codex agent's reasoning becomes the same events. `threadParams` sends `model_reasoning_summary: 'auto'` (the most detailed summary the model has) on every start kind, so a resume and a side run's fork ask the same; without it codex 0.164.0 sent each `reasoning` item with an empty `summary` (`turn/start`'s own `summary` works too, but the thread config rides on every start kind). `CodexEventMapper` maps a main-thread `item/reasoning/summaryTextDelta` to `thinkingDelta`, a `summaryPartAdded` past the first part to a `\n\n` delta, and a completed `reasoning` item's non-blank `summary` parts, joined by blank lines, to `thinking` with `startedAt`, the item's `startedAtMs` from `item/started`: codex writes the summary as the reasoning ends, so the first delta comes late, and `ChatService` times the kept item from `startedAt` (never past its end). The raw reasoning (`item/reasoning/textDelta`, the item's `content`) is never shown, and a child thread's reasoning shows nowhere, as a Claude subagent's thinking does. A summary is often just a bold title per step (`**Checking prime divisors**`). `backend/tests/fixtures/codex/codex-reasoning-summary.jsonl` is a real 0.164.0 run, trimmed to its thread, turn and item lines.

**Probe.** `npm run e2e` ends with `e2e/thinkingProbe.mjs --soft` (see [E2E](e2e.md)), which runs the app's own check against the real CLI and one short Sonnet run with the flag.

# ZumiBot Documentation Site Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the end-user documentation site for ZumiBot (about 60 pages, from install to the most advanced feature) as a new `zumi-bot-docs` workspace, deployed on Vercel and live at `https://docs.zumibot.run` once its prerequisites land.

**Architecture:** An Astro Starlight site in its own npm workspace, built to static HTML with Pagefind search, themed with the `zumibot.run` brand. Pages are Markdown/MDX under `src/content/docs/<group>/`. Unit tests (vitest project `docs`) guard against leaks, broken code blocks, drift from the site's install commands, and missing screenshots. Screenshots come from a script that reuses the e2e harness (Local mode, fake `claude`).

**Tech Stack:** Astro 7.4.13, `@astrojs/starlight` 0.43.1, `starlight-links-validator` 0.27.0, `@fontsource-variable/bricolage-grotesque` 5.3.0, vitest, Playwright (through `zumi-bot-server/e2e/harness.mjs`), Vercel.

**Spec:** `docs/superpowers/specs/2026-11-20-docs-site-design.md`. Read it before any task; this plan argues from it.

## Global Constraints

- Exact versions, no ranges: `astro` 7.4.13, `@astrojs/starlight` 0.43.1, `starlight-links-validator` 0.27.0, `@fontsource-variable/bricolage-grotesque` 5.3.0. The workspace `version` equals the other workspaces' (0.1.2 today).
- `engines.node`: `22.x`. Astro needs Node `>=22.23.4`; the owner's machine has 22.23.3, so update Node before Task 1.
- Nothing third-party loads at view time: no CDN, no Google Fonts, no analytics.
- Never link to the GitHub repo or the private release. Never name the owner's servers: examples use `zumibot.example.com`.
- Server install commands use `https://zumibot.run/releases/latest/install.sh`, the same as the site's `installSteps()`.
- Leak list (verbatim from the spec): `github.com/MhdAljuboori`, `raw.githubusercontent.com`, `mhdaljuboori.me`, `zumi-bot-server/`, `docs/architecture`, and source paths such as `src/<name>.ts` or `.tsx`.
- Writing: plain, second person, short sentences, US spelling, the tone of `CHANGELOG.md`. Each page is written fresh from its `docs/architecture/` doc and checked against the app. No file names, module names, internal paths, dev-only env vars or test hooks. Only released behavior; a later-phase or "to verify" part is left out or named as not available yet. UI labels are quoted exactly as the app shows them.
- Page shape: what it's for (one or two sentences) → how to use it (numbered steps, screenshots) → tips and limits → related.
- Slugs are the file paths below and never change once the site is live.
- **No commits.** The owner's rule: commit only when the owner says so. Each task ends at a checkpoint where the owner reviews; if they ask for a commit, it is one paragraph of 15–25 words with no `feat:`-style prefix and no Co-Authored-By line.
- Before changing an area of the repo, read its `docs/architecture/` doc (root `CLAUDE.md`).

## Review Focus

1. **A reader on a phone**: at 375 px wide the sidebar opens from the menu button, and screenshots, tables and code blocks scale or scroll inside the page. Nothing scrolls the whole page sideways. Checked in Task 4's browser step.
2. **A reader whose theme differs from the system**: switching Starlight's theme picker switches every screenshot, not just the page colors. Checked in Task 4's browser step.
3. **Search under the strict CSP**: typing in search returns results with no CSP violation in the console, on a deep page as well as the home page. Checked in Task 3's browser step.
4. **Pasting a command**: what the copy button copies runs as is, with no leading `$ ` prompt and no curly quotes. Guarded by `codeBlockProblems()` (Task 2), which runs over every page.
5. **A screenshot that is referenced but missing, or listed but never made**: the build or the tests fail, never the reader. Guarded by `tests/shots.test.ts` (Task 4).

# Pause and Resume

**Pause and Resume (`shared/src/pause.ts`, `core/chat/pauseSettings.ts`, `pauseHook.ts`, `chatTmp.ts`).** **Pause** beside Stop (`chats:pause`, `TaskQueue.pause`; refused on an idle, compacting, already paused or A→B chat) lets the running subagents and main-thread calls finish, starts nothing new and ends the run once the agent has written its status; Resume continues on the same session, which holds every subagent result. **The hook.** Every main run (single-chat turns, room members, routines, A→B asked runs; never a side run or a Compact, whose settings stay byte for byte apart from the agent's own extension parts, see [Servers, plugins, skills and hooks](extensions.md)) gets one more `--settings`, merged by `oneSettings` into the one with the desktop ask rules: a `PreToolUse` hook (matcher `*`) running `[ -e "$ZUMIBOT_PAUSE_FILE" ] || exit 0; exec <node> dist/pauseHook.mjs`, so outside a pause a call costs one shell test, and env and hooks never enter the prompt, so the cache prefix holds. The run's env names the flag, `<data>/pause-flags/<hash>/paused`: outside the chat's `CLAUDE_CODE_TMPDIR`, which the agent can write (Sandboxed and Container alike), so the agent can neither swap the flag for a symlink that makes the server's write land on another file nor delete it to dodge a pause. A container gets the flag's folder mounted read-only. `blocks` lets a call with a top-level `agent_id` through (the CLI sets it only inside a subagent, even in an `--agent` session) and blocks a main-thread call, or unreadable input, with exit 2 and `PAUSE_BLOCK_TEXT`, which carries `PAUSE_MARKER`; a call already running is never touched. `blocks` also lets a top-level `tool_name` of `collaborationwait_agent` or `collaborationlist_agents` through (no Claude tool has those names), so a paused Codex main thread can wait for its subagents. A Codex main run gets the same hook as a `-c` hook on its app-server's argv instead (`codexPauseHook`, timeout 30, which runs node without `exec` and turns any failure into exit 2, since Codex lets a call run on exit 1 or a timeout), trusted and checked with the vault's hooks, and its rounds come from the per-response ids the Codex mapper gives (see [Codex agents](codex.md)). Without the built entry (`pauseHookOf` null) the server logs `pause hook unavailable` and runs as before, and `chats:pause` is refused with "Pause is unavailable: the pause hook is missing from this build" (`ChatService.canPause` needs the hook and `tmp`, and for a chat with a Codex agent, a room member included, `codexPauseHook` and the `pause` cap; `PAUSE_UNAVAILABLE`). `runPauseHook` (in `pauseSettings.ts`, so the test fixture runs the same code) is fail-closed and exits once: stdin closing without its end counts as the end, and a read error, no input within 10 s or a stderr it cannot write all block. **State.** `pause()` writes `ChatMeta.pause: 'pausing'` with `held: true` in one write before the flag (a crash mid-pause keeps the tray held), then the flag (`setPauseFlag`; a failed write is logged by code only), then `GroupService.requestPause`, then pushes a fresh meta; before any spawn a flag whose chat is not pausing is removed (`dropStaleFlag`). The pause lands however the run ends (`finishPause`/`landPause`, checked inside the write): `paused`, the tray held, the flag removed and the `userPaused` notice ("Paused. Press Resume to continue.") after whatever the end wrote (`stopped`, `interrupted`, an error). The older `paused` notice kind is the room hop cap's; `userPaused` is this feature's. The pause end counts as a normal reply end for unread and notifications, and a Stop while pausing keeps the tray held instead of starting the oldest task. The pump lands an idle chat still `pausing` (the reply ended between `busy()` and the write, or a room had already settled its end, when `requestPause` is false) under the chat's lock, so an Edit can't save between the landing's read and write, and starts nothing for a `paused` one, at start-up too. **Safety cap.** The run is stopped (its own handle, no `stopped` notice, an `ok` end) once 3 model responses (`PAUSE_BLOCK_CAP` rounds; calls of one `message.id` are one round, since the CLI runs tools while a response streams) had a blocked main call, judged only on a blocked result while no main call is open and no dispatch runs, so the agent always gets a request to read its results, and counted only while this server set the flag, so an agent printing the block text cannot stop itself. **Resume** (`chats:resume`, `resumePaused`, `paused` only) clears pause and held and sends `Continue` (`RESUME_TEXT`) under the lock, so held tasks go after it; it names the Continue's message id first and hands it to `TaskQueueDeps.onResume` before the send starts (`GroupService.resume` posts under it too), so a routine run or a workflow Agent step can follow it. The user taking over (their own message into an idle paused chat, Send now, Edit, Resend, a version switch: `takeOver`) ends the pause too, keeping `held` only while tasks are queued; `submit(..., 'routine')` and any send into a busy paused chat queue held. **Rooms.** `requestPause` drops agent replies from the inbox and starts nobody; the pass ends when the running members end, and the room stores `GroupInfo.paused` `{members, queue, reasons}` (who was working, the waiting turns and why each waits). Resume posts `@m1 @m2 … Continue` to those members and restores the queue after them; a message the user types clears it. **Routines.** A run into a pausing or paused chat queues its message held (the run stays `running` until that message is answered after Resume) and skips `sessionPolicy: 'fresh'`'s fresh start, so the paused session survives; a run whose own turn the user paused is `paused` (`RunStatus`; not failed, no endedAt, still counted among the routine's unfinished runs, and a limit that ended the pausing turn waits for Resume, not the reset; an error in that turn still fails it), and `RoutineRunner.chatResumed` (queued behind the paused turn's own idle) moves it onto Resume's Continue as after a limit `continue`, counting `resumes` (Recent runs: "Paused by you · press Resume in its chat to continue", then "Resumed after a pause"), while a message of the user's own ends it silent as "Continued by hand"; `recover()` keeps a paused run waiting without a write, and pauses a running one whose turn a restart ended paused; a limit wait that comes due in a paused chat ends "Continued by hand". **Restart.** `recoverInterrupted` turns an `inFlight` `pausing` chat into `interrupted` plus `userPaused` and `paused` (held only when tasks are queued; `ChatMeta.pause` gates everything), and a room keeps or builds `GroupInfo.paused`; an idle `pausing` one gets the notice. A chat already `paused` whose last item is not a `userPaused` notice (a crash between the paused write and the save: an idle single chat, or a room still `inFlight` because `landPause` runs before it clears it) gets the notice the same way, so the Resume pill shows. **Killed subagents.** A turn that ends stopped or interrupted (Stop, a Stop while pausing, a server shutdown; never a pause's wrap-up or the cap) stores the descriptions of its top-level dispatches killed by it as `ChatMeta.lost` (per member in `GroupInfo.lost`): those running when `ChatService.stop` was called (the slot's `onStop` notes them, since the CLI's SIGINT aborts the running query first and may close them `failed` before it exits) that did not end `done`, plus any started during the wind-down and still running; that agent's next plain `--resume` turn gets `lostNote` after the to-do note (never a chat item), cleared at that run's first CLI event, and a cut run or reseed (Edit, Resend, a version switch) clears it with no note. A hard crash records nothing, since dispatch entries are written at turn end. **UI.** `pause-button` beside Stop (`pauseControl` in `state/pause.ts`: hidden while compacting and in an A→B chat, disabled while pausing), `PausingLine` ("Pausing — waiting for N subagents", N from the running dispatch entries) over the composer, the Resume pill on the latest `userPaused` notice (`resumeRow`), and `sendsAsTask`/`tasksHeld` treat a paused chat like a held one.
